# Phase 18.13: Git Discovery Service and First-Party `@clay/git` Package

## Objectives

- Add a typed server-owned Git discovery service for known workspace roots without granting arbitrary shell authority.
- Discover repository root, current branch or detached HEAD, dirty/clean summary, changed-file count, and last refresh status.
- Cache Git status per workspace with explicit refresh and bounded polling that never blocks typing, rendering, completion, or paint.
- Create first-party `@clay/git` as a read-only package consuming typed Git APIs for status UI, Control Center commands, and transient pickers.
- Document Clay JS APIs, configuration hooks, package guide changes, generated registry entries, wiki pages, and tests for repo/non-repo roots, parsing, timeout/error handling, and no shell/network authority expansion.

## Expected Outcome

- Clay shows repository and branch state for the active workspace through explicitly loaded first-party `@clay/git`.
- Git workflows reuse typed server commands, transient menus, shell panels, workspace roots, and package UI primitives.
- Git command execution is narrow, bounded, sanitized, workspace-rooted, timeout-protected, and read-only by default.
- Mutating Git commands are deferred unless a later plan/decision grants explicit command authority.
- All public programmatic surfaces are exposed as documented Clay JS APIs with generated registry coverage, and the code wiki is updated.

## Compromises Made

- **Read-only only**: Phase 18.13 intentionally defers all mutating Git operations (checkout/stage/commit/push/pull/etc.) to a later phase. `@clay/git` and `clay:git` therefore expose no mutation surface; users must use external Git tooling for now.
- **No automatic refresh**: Status is refreshed explicitly or by bounded stale polling. Continuous background polling is avoided to keep Git work off typing/paint paths.
- **Fixed safe defaults**: Discovery timeout (750ms) and stale-poll interval (5s) are hard-coded constants in this phase. No user-facing configuration surface exists yet.
- **Panel-only UI**: `@clay/git` ships a single read-only SDUI status panel. Branch/status pickers and Control Center commands are exposed as server-first commands, but no transient branch picker UI is built in this phase.
- **Server-owned Git authority**: Packages cannot spawn Git or provide Git argv. This keeps authority narrow but means new Git operations must be added server-side with their own command IDs and validation, not by extending the package manifest.
- **Timing-sensitive cache tests require fake-git helpers**: Cache coalescing and stale-polling tests rely on a fake Git executable and careful wall-clock handling; the tests were hardened with rendezvous/timestamp pinning, but they remain heavier than pure unit tests.

## Further Actions

- **Future mutation authority**: Add explicit user-approved permission grants and closed server command IDs for staged operations (e.g. `clay.git.stageFile`, `clay.git.commit`). Each operation must include workspace-root validation, conflict handling, and network authority for remote operations.
- **Transient branch/status picker**: Build a package-owned transient menu session that lists branches or recent changes and routes selections through server-first command IDs, reusing the `TransientMenuSession` primitive from Phase 18.8/18.12.
- **Configurable Git defaults**: If user tuning becomes necessary, expose `clay.contributions.configuration` entries for discovery timeout and poll interval through a new permission grant, rather than environment variables.
- **Persistent background refresh**: Evaluate a low-frequency background task that refreshes stale roots during idle time, with explicit cancellation and hot-path exclusion.
- **Multi-root status aggregation**: When many workspace roots exist, consider summarizing aggregate branch/dirty state in the shell chrome instead of one panel section per root.
