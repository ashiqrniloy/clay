# Phase 18.10: Package-Provided Tree-sitter Grammar and Syntax Highlighting Primitive

## Objectives
- Add a generic `SyntaxGrammarContribution` primitive so packages can provide Tree-sitter grammar artifacts, highlight queries, style-token mappings, provenance, and performance metadata.
- Create first-party grammar-only packages `@clay/rust`, `@clay/typescript`, and `@clay/javascript` without full language modes, language-specific commands, completion providers, or bespoke Rust branches.
- Parse and highlight Rust, TypeScript, and JavaScript through server-side background work that publishes bounded `DecorationSet` values to the existing client decoration renderer.
- Keep active syntax grammar separate from active major mode so grammar packages can attach highlighting to `core.code`/`core.text` fallback documents from Phase 18.9.
- Preserve hot-path, authority, and package-security invariants: no package JavaScript in Masonry paint/text-event handlers, no client-side parser execution, no arbitrary native/third-party grammar artifact loading, no filesystem/network/shell/AI/WASM/raw-op/native-widget/package-manager authority expansion.

## Expected Outcome
- Opening Rust, TypeScript, and JavaScript files can show syntax highlighting sourced from explicitly loaded first-party grammar packages while documents still use generic fallback modes unless a full mode package later takes ownership.
- Clay core owns the grammar contribution contract, Tree-sitter execution boundary, validation, parse scheduling, decoration transport, and renderer safety; packages own grammar/query assets and language metadata.
- Syntax parse/highlight work is asynchronous, cancellable, stale-version-rejecting, viewport-prioritized, and bounded by existing parse/decorator budgets.
- Tests and docs prove grammar resolution, disabled/invalid package fallback, query diagnostics, decoration payload limits, and absence of language-specific Rust server/client branches.

## Entry Gate

- Do not start until Phase 18.9 generic `core.text`/`core.code` fallback modes and deterministic document classification fallbacks are complete (`plans/037-Phase18.9-Generic-Text-Code-Modes-Key-Behavior-and-Mode-Discovery-Fallbacks.md`).
- Treat arbitrary third-party grammar/native artifact loading as out of scope. This phase may load only resolver-validated first-party package grammar artifacts. If implementation needs broader native, third-party, package-manager, filesystem, or WASM authority, stop and request an approved decision log before coding that expansion.
