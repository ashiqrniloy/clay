# Phase 20.8: UI Reference Documentation and Agent Convention Maintenance

Source: `roadmap.md` → Phase 20.8. Entry gate: Phases 20.1 and 20.4 must have landed; then run continuously alongside Phases 20.5–20.7. As of this plan, Phases 20.1–20.7 (plans 062–068) are complete, so this plan performs the catch-up maintenance pass: lock the living-documentation conventions, add the missing `docs/reference/` UI components page, reconcile accumulated catalog/guide drift, and install CI gates so future documentation drift fails `cargo test` rather than silently rotting.

## Objectives

- Lock `.agents/skills/clay-ui/references/components.md` and `references/tokens.md` as the complete, current single source of truth for reusable components, primitives, style variables, tokens, and layout rules, and establish the convention that every later UI phase updates them in the same change.
- Keep `docs/reference/packages/creating-packages.md` accurate for every implemented-vs-planned component, token, and layout capability, with status markers that match the catalog.
- Add a `docs/reference/ui-components.md` page that links the component catalog, token tables, conformance rules, and package authoring contract so any agent or developer can discover every reusable UI primitive/component and the rules for using them without reading paint code; link it from `docs/index.md` and the code wiki navigation.
- Verify `.agents/skills/create-plan/references/clay.md` (the create-plan UI requirements) stays aligned with the implemented catalog and the `clay-ui` skill references.
- Add a CI drift test so documentation drift — catalog ↔ `creating-packages.md` ↔ `docs/index.md` ↔ `docs/reference/ui-components.md` ↔ create-plan UI requirements — fails `cargo test` with an actionable update message.

## Expected Outcome

- Any agent or developer can discover every reusable UI primitive/component and the rules for using them from `docs/reference/ui-components.md` plus the `clay-ui` skill references, without reading paint code.
- `docs/reference/packages/creating-packages.md` status markers match the `clay-ui` catalog exactly; no implemented component is marked planned and no planned component is marked implemented.
- `docs/index.md` links the UI components page, and the code wiki navigation references it.
- `.agents/skills/create-plan/references/clay.md` names the catalog files and conventions that actually exist.
- `cargo test` fails when the component catalog, token catalog, package authoring guide, master index, UI components page, or create-plan UI requirements drift out of agreement, with a message naming the file to update.
