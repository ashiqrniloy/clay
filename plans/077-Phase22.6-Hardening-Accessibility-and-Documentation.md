# Phase 22.6: Hardening, Accessibility, and Documentation

This plan implements `roadmap.md` Phase 22.6. Phases 22.1–22.5 (Plans
072–076) shipped the full window model: equal-area splits, per-pane document
views, tabs as independent clients with a server-authoritative registry,
keyboard tab management, and tab × split persistence. Phase 22.6 hardens
that model for production: accessibility for the tab bar, tab cards, and
panes; CI-guarded performance budgets for the new window paths; an authority
review proving per-tab grants do not leak; protocol compatibility tests; and
documentation (primitive references, generated registry, docs index, wiki).

Scope boundary: this phase adds **no new protocol messages, no new package
extension points, no new modes/packages, and expects no new public Clay JS
APIs or configuration surfaces**. Accessibility is internal chrome metadata
(AccessKit), budgets are internal constants + deterministic tests, and the
authority work is review + regression tests. If any task discovers a genuine
new public surface, it is exposed through the Clay JS API flow, not silently.

No primitive-review task is required (no mode/package/reusable-editor-
capability changes; create-plan reference `clay.md` triggers on those).
A Clay UI catalog review task is included because accessibility annotations
touch cataloged UI surfaces (tab bar chrome, pane hosts).

Confirmed architecture references:

- Roadmap Phase 22 preamble and Phase 22.6 focus areas (`roadmap.md`).
- Plans 072–076 (Phase 22.1–22.5) for the split tree, pane host, tab
  registry, and persistence architecture.
- `.agents/skills/project-patterns/references/planning-checklist.md`,
  `protocol-and-performance.md`, `authority-boundaries.md`,
  `maintenance-validation.md`, `doc-registry-tests.md`.
- AccessKit via Masonry: `masonry = 0.4.0` re-exports `accesskit = 0.21.1`
  (vendored sources under `~/.cargo/registry/src/*/`); `Role::TabList`/
  `Role::Tab`, `Node::set_label/set_selected/set_live` (`Live::Polite`),
  `ctx.request_accessibility_update()` in `masonry_core-0.4.0`.

## Objectives

- Accessibility: correct AccessKit roles/names for the tab bar, tab cards,
  and panes, focus movement consistent with the Phase 22 keyboard model, and
  screen-reader announcements for tab switch and split changes.
- Performance: budgets for per-pane paint, tab switch latency, and
  multi-pane decoration traffic, guarded by deterministic CI tests in the
  same style as the Phase 14/16 budgets.
- Authority: verified per-tab workspace grants and package scopes with
  regression tests proving no cross-tab leak.
- Protocol compatibility tests for the Phase 22 window-management messages.
- Documentation: primitive reference docs, generated registry entries, docs
  index links, example-config check, manual test plan, and code wiki updates.

## Expected Outcome

- A screen reader can navigate the tab bar (TabList), tab cards (Tab with
  workspace names and selected state), and panes (labeled Group/Document
  nodes) with focus order matching the keyboard model; tab switches and
  split changes produce polite live-region announcements.
- New budget constants in `src/perf/budgets.rs` pinned by deterministic
  tests (`cargo test` is the CI gate, matching Phase 14/16 style) plus
  advisory Criterion baselines; `docs/development/performance.md` documents
  them.
- A passing authority review recorded with regression tests: tab A's
  workspace grants are unreachable from tab B's connection, and package
  scopes are unaffected by tab membership.
- Phase 22 protocol messages round-trip the codec and the protocol version
  is pinned by a compatibility test.
- Primitive references, the generated Clay JS doc registry, `docs/index.md`,
  the manual test plan, and the code wiki all reflect the Phase 22 window
  model and this phase's hardening.
