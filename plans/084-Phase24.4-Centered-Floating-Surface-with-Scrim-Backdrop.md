# Phase 24.4: Centered Floating Surface with Scrim Backdrop

Prerequisite: Plan 083 (Phase 24.3 — Path Mode: Dired-Style Filesystem Browsing) is complete with 18 checked tasks and zero unchecked tasks. The working tree was clean when this plan was created.

Scope boundary: this phase changes only Command Centre presentation and accessibility. It adds a centered origin, a window-level Masonry overlay layer, token-driven width and scrim paint, modal input containment, and filtered-result announcements. It does **not** change command/path behavior, filesystem authority, fuzzy scoring, command execution, default keybindings, or package APIs. Multi-stroke keybindings, final chord defaults, and menu latency budgets remain Phase 24.5. Completion pickers remain bottom-anchored; context menus remain pointer-anchored; menu-bar overlays remain main-area anchored. No backdrop blur, offscreen render target, shader, or custom Vello filter pass is added.

Approved decision source: `decision-logs/2026-08-11-1711-command-centre-surface-path-mode-and-sequence-keybindings.md`.

## Objectives

- Present both `controlCenter.open` and `controlCenter.openPath` as one centered Spotlight-style floating surface at window level, including split-pane and tab-bar layouts.
- Dim the complete Clay window behind the surface with a theme-token-driven translucent scrim.
- Reuse `TransientMenuSession`, `TransientPackageOverlay`, `PackageOverlayHost`, Masonry’s native root-layer API, and existing retained component rendering instead of creating another overlay system.
- Expose a named modal dialog with nested menu semantics, contain keyboard/pointer interaction while open, and announce filtered result counts without repeated announcements on selection-only updates.
- Preserve current server authority, bounded snapshots, command/path activation behavior, package denial, and non-centered transient surfaces.

## Expected Outcome

- Command mode and path mode open as a single centered panel over a translucent full-window scrim; the panel remains centered and width-clamped as the window resizes.
- Completion, context-menu, menu-bar, and package overlay geometry remains unchanged.
- Screen readers receive a modal `Dialog` named from the sanitized menu prompt, a nested `Menu`/`MenuItem` tree, and a polite result-count status.
- While a centered modal session is open, unhandled keys and pointer events cannot reach editor content; Escape closes through the existing server-owned cancel path, and prior editor focus remains available after close.
- Paint/layout work is constant with respect to document size: one full-window scrim fill plus the existing bounded overlay subtree, with no blur/filter/offscreen pass.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, and `cargo bench --no-run`.
