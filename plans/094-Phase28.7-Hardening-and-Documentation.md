# Phase 28.7: Hardening and Documentation

This plan implements `roadmap.md` Phase 28.7. Phase 28 completes the
generic command/edit/intelligence primitives whose data already exists
and fixes the 2026-08-18 command/provider defects. Phases 28.1–28.6
own the implementations (keymap parse, comment/line transforms,
folding, link/hover intent, inlay hints, completion ranking). Phase
28.7 hardens that set: behavior-parity and protocol-compatibility
tests, CI-guarded budgets, authority review for the new intents,
the `js_runtime` test-module move, generated registry / API inventory
/ primitive-reference / wiki coverage, and the manual test plan.

**Prerequisite (hard):** Phases 28.1–28.6 must be implemented and
their plan checkboxes complete before this plan's implementation
tasks start. The initial entry-gate run on 2026-08-20 (`rustc 1.96.1`,
Linux x86_64) is historical: it was **blocked** because no
`plans/*Phase28.[1-6]*` files existed. Plan 095 now exists with its implementation/maintenance tasks complete.
A fresh Linux gate re-run on 2026-08-20 is recorded under Task 1; the
historical test blockers were fixed and the final all-target gate is green,
so later hardening tasks may proceed. The historical pre-28 surfaces and test
blockers remain preserved under Task 1 for provenance; they are not the
current Phase 28 inventory.

Scope boundary: this phase adds **no new editor mode, language mode,
first-party JS package, package extension point, package-facing UI
component, theme token, layout rule, or reusable primitive category**. It
does not change package-runtime trust domains or add filesystem, network,
shell, WASM, or AI-mutation authority. Existing Phase 28 UI/accessibility
follow-up defects and verification gaps are in scope only as host-owned
bug fixes, semantic/a11y coverage, and visual recapture; they must use the
Clay UI preflight/catalog and mandatory visual-review task below. No new
package component or token is justified. If a task discovers a genuine new
public surface that 28.1–28.6 forgot to expose, it goes through the Clay JS
API / configuration tasks — not a silent Rust `pub`.

## Objectives

- Behavior-parity and protocol-compatibility tests for every Phase 28
  command, hover/click intent, and decoration kind.
- Phase 28 budgets CI-guarded in the Phase 14/16/22.6/24.5/26.7 style
  (deterministic structural gates now; wall-clock remains advisory
  until Phase 21 promotion).
- Authority review proving link activation and hover intents stay
  under existing package permissions and cannot mint filesystem,
  network, shell, or workspace grants.
- Move the `src/server/js_runtime/mod.rs` inline test mass (~10.1k
  lines, 198 tests) to a sibling `tests.rs` — move only, no behavior
  change.
- Generated registry, API inventory, primitive reference docs, package
  authoring notes, example `init.js`, manual test plan, and wiki all
  record the Phase 28 primitive set so new formats consume it
  declaratively.
- Plan 095's live-review follow-ups are owned here: resolve the GUI
  `lsp-shared` worker failure and inlay recapture, repair editor
  editable-text semantics, complete completion/link/fold accessibility and
  visual recapture on a stable compositor, rerun transform/resize states,
  and keep completion-recency expansion telemetry- and decision-gated.

## Expected Outcome

- Every Phase 28 command (`editor.toggleComment` / package-backed
  comment and prose transforms), fold publish/toggle, link/hover
  intent, inlay decoration, and shared completion scorer has a
  failing-if-broken automated check.
- New and existing Phase 28 wire messages round-trip the rkyv
  length-prefixed codec; `PROTOCOL_VERSION` is pinned to whatever
  28.1–28.6 left (23 on the current tree; the original pre-28.7 gate
  record below is historical).
- Budget constants for folding payloads, inlay/link decoration
  bytes, hover-intent payloads, and completion ranking sit in
  `src/perf/budgets.rs` with deterministic tests; ranking and intent
  work stay off the keypress-to-local-paint path.
- Link click and hover intent cannot be reached by package code as a
  grant; `render-decorations` / `render-folding` / `parse-document`
  stay distinct.
- `src/server/js_runtime/mod.rs` is reviewable implementation only
  (~1.5k lines); the same 198 tests run as `server::js_runtime::tests::*`.
- Primitive registry, Clay JS API docs, `docs/index.md`, generated
  registry, `examples/init.js`, `test-plan/`, and `docs/wiki/` match
  the shipped Phase 28 surface.
- Plan 095's P1/P2 review findings are either fixed and re-captured with
  evidence, or remain explicitly `UNRESOLVED` with a host/tooling blocker;
  no inlay, editable-text, link, fold, transform, resize, or ranking claim
  is inferred from structural tests alone.
