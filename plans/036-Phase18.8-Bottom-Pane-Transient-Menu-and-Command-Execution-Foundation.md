# Phase 18.8: Bottom Pane Transient Menu and Command Execution Foundation

## Objectives
- Add one reusable Clay-owned transient menu session model for bottom-pane command browsing and future picker workflows.
- Promote command declarations from metadata-only discovery to validated server-first command execution.
- Implement Control Center as the first consumer without one-off UI or command-routing logic.

## Expected Outcome
- A bottom-pane transient menu can list/filter registered commands, show key bindings/status/provenance, cancel safely, and execute the selected command.
- SDUI actions, package UI actions, keybindings, and transient-menu selections route through one server-authoritative command execution path.
- Ordinary typing/rendering remains independent of command search/execution and never waits on JavaScript, IPC, file IO, AI, shell, or full-document serialization.
