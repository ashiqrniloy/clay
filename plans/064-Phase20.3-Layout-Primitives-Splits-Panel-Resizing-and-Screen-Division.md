# Phase 20.3: Layout Primitives — Splits, Panel Resizing, and Screen Division

This plan implements `roadmap.md` Phase 20.3. It turns the existing `PaneSplitTree` and `FixedSlotState` model (Phase 18.2) into user-facing interactive layout primitives with safe package access, building on the Phase 20.2 chrome primitives (`paint_divider`, `paint_panel_chrome` with resize/collapse `InteractionState`).

Scope boundary: Phase 20.3 ships **interactive layout behavior** (drag, resize, collapse, persistence, layout intents, focus routing across splits) and the structural tests/docs for it. It does **not** restyle components (Phase 20.4), add overlay/menu/input component kinds (Phase 20.5), segregate themes (Phase 20.6), or add conformance guardrails (Phase 20.7).

Entry gate: Phase 20.2 plan (`plans/063-Phase20.2-Clay-UI-Primitive-Library-Foundation.md`) must have zero unchecked tasks. Use the current project UI skill requirements before implementation.

## Objectives

- Make `PaneSplitTree` splits draggable: pointer-down on a split divider starts a drag, pointer-move updates the `SplitRatio` with min/max clamping, pointer-up commits.
- Make fixed slot panels (`left`/`right`/`top`/`bottom`) resizable via drag handles, with min/max clamping from `PanelDefaults` tokens, collapse/restore toggle, and `resized_by_user` tracking.
- Persist user-modified split ratios and fixed slot sizes across sessions (serialize to `~/.config/clay/layout.json` or equivalent XDG path, restore on startup).
- Add inert, versioned layout intent primitives so packages can request additional panes/splits through `clay:ui` without native mutation.
- Implement focus and input-routing behavior across splits and panels, including transient surface anchoring inside split layouts.
- Add structural layout tests: geometry invariants, resize clamping, collapse/restore, persistence round-trip, no-layout-mutation-during-layout.
- Document layout primitives in `docs/reference/packages/creating-packages.md` and the clay-ui catalog.

## Expected Outcome

- Users can split the screen (horizontal/vertical), drag split dividers to resize, and drag panel edges to resize all four fixed slots; sizes clamp to token-defined min/max; panels collapse/restore; sizes persist across restarts.
- Packages can request split layouts through inert versioned layout intents validated by Clay; they cannot mutate native layout directly.
- Focus moves correctly across splits and panels; transient surfaces (overlays, menus) anchor correctly inside split layouts.
- Structural tests prove geometry invariants, clamping, collapse/restore, persistence round-trip, and no-layout-mutation-during-layout.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`.
