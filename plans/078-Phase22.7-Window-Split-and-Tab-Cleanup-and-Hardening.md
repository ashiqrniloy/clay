# Phase 22.7: Window Split and Tab Cleanup and Hardening

This plan pays down the debt found in the full review of the `feature/tab_window_split` branch before Plan 079 (Phase 22.8, Per-Tab Workspace and Document Isolation) starts. It fixes every issue raised in that review: architectural weaknesses (rejected-close kills connection, registry entries never expire, implicit connection-owner contract), clarity problems (the 6195-line `main.rs` god file, repeated downcast boilerplate, second god object `PaneDocumentView`), overengineering (dead scaffolding behind `#![allow(dead_code)]`, v1 writer kept alive only by frozen tests), implementation gaps (the `active()` paint panic invariant, missing `PaneContentHost` tests, tab bar overflow, debug `eprintln` in the event bridge), and flexibility limits (Vim-style split naming baked into the command surface, undocumented `PaneContent` extension seam).

Scope boundary: this phase changes NO product behavior except three deliberate ones — a rejected tab `Close` no longer terminates the sender's connection, the tab bar gains horizontal scroll once cards hit a minimum width, and two additive direction-based split command aliases are added. Everything else is refactor, hardening, deletion, tests, and documentation. Per-tab workspace/document isolation is explicitly OUT of scope (Plan 079). The server's shared `WorkspaceState`/`DocumentState` singletons and the per-connection snapshot broadcast model stay untouched here (recorded in Compromises/Further Actions).

## Objectives

- Eliminate every live panic path in the shell tab/pane lifecycle (the `active()` invariant is enforced and regression-tested).
- Make the server tab-close path authority-correct: rejected closes never terminate the sender's connection.
- Bound the tab registry: abandoned entries expire deterministically instead of leaking forever.
- Delete dead code: unused layout scaffolding types, stale `#[allow(dead_code)]` markers, the production v1 layout writer, the per-event debug print.
- Document and test the connection-owner contract (the chrome `EditorWidget` may be an invisible zero-size orphan and must keep receiving events) and the `PaneContent` extension seam.
- Give the tab bar a non-degrading overflow behavior (minimum card width + horizontal scroll).
- Add additive direction-based split command aliases without breaking existing command IDs or key bindings.
- Extract the driver's tab/restore/reconcile subsystem out of `main.rs` into cohesive modules with typed widget-access helpers, keeping all 60+ binary tests green.
- Decompose `PaneDocumentView` field groups into helper structs without behavior change.
- Keep the full suite green (`cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, all test targets) on Linux at every step.

## Expected Outcome

- `main.rs` shrinks by roughly 2500–3000 lines; `Driver` lives in `src/driver/` with `tabs`, `restore`, and reconcile logic in named modules; repeated `try_downcast` boilerplate collapses into 3 typed helpers.
- `ClayShellWidget::active()` can no longer panic on any reachable state; zero-tab shells lay out, paint, and ignore commands safely.
- Server `TabCommand::Close` keeps the connection alive on rejection and pushes a reconciling snapshot.
- `TabRegistry` entries carry `last_activity` and expire via a swept TTL; registry size is bounded in long-running servers.
- `src/shell/layout.rs` carries no `#![allow(dead_code)]`; dead observation/component types are gone; the v1 layout writer lives under `#[cfg(test)]` only.
- Tab bar renders ≥1 tab card at a readable minimum width and scrolls horizontally when tabs overflow; wheel input on the bar scrolls.
- `clay.shell.clientSplitPaneRight` / `clay.shell.clientSplitPaneDown` resolve to the existing vertical/horizontal split handlers; old IDs and defaults unchanged.
- Connection-owner and `PaneContent` contracts are documented in code and wiki with regression tests (close pane 1 with siblings keeps the owner wired).
- No user-visible regression: split/close/tab/restore flows, theme stamping, dividers, focus ring, status line, accessibility announcements unchanged.

      - No expiry, document the leak: rejected — Plan 079 attaches heavyweight per-tab state to entries; unbounded leak becomes real memory debt.

    - API Notes and Examples:
      ```rust
      pub(crate) fn sweep_expired(&mut self, now: Instant, ttl: Duration) -> Vec<TabId> {
          let mut removed = Vec::new();
          let mut last_kept = None;
          self.tabs.retain(|row| {
              if now.saturating_duration_since(row.last_activity) < ttl {
                  last_kept = Some(row.entry.tab_id);
                  true
              } else {
                  removed.push(row.entry.tab_id);
                  false
              }
          });
          if !removed.is_empty() {
              if self.active.is_some_and(|active| removed.contains(&active)) {
                  self.active = last_kept;
              }
              self.revision += 1;
          }
          removed
      }
      ```

## Compromises Made

- **Baseline note (entry gate)**: lib 1343 passed / 2 ignored; bin 62; protocol 147; runtime 197; editor 158; security 123; 2030 total, all six benches `Success`; `src/main.rs` 6195 lines, `src/masonry_shell.rs` 4634, `src/masonry_pane_document.rs` 3961. Corrected during evidence recording: the draft baseline swapped the runtime/editor counts; the numbers above are the actual gate-run counts.
- **`last_activity` lives on a `RegistryEntry` wrapper, not on `TabEntry`** (the plan's literal "every `TabEntry` carries `last_activity`"): `TabEntry` is rkyv-serialized into every IPC snapshot and `Instant` is not serializable; the Phase 22.6 grants-nothing shape test pins the protocol side.
- **Connection-owner contract needed a structural fix, not docs-only**: the probe proved `pending_orphans` drained the editor host on close-then-split churn, detaching the connection owner (`edit_widget` panic). `chrome_orphans` + `editor_pane_id` were added; the plan's "docs + tests only" choice was recorded as rejected post-probe.
- **Tab bar overflow uses wheel-driven offset, not a `scroll` component strip or overflow menu** — recorded ceiling: no scrollbar chrome, drag-to-scroll, or touch gesture; cards clip at the `+` boundary.
- **Split aliases carry no default chords**; canonical IDs and Ctrl+\ / Ctrl+- bindings unchanged (additive-only).
- **`move_left`/`move_right`/`move_to` kept as three methods** (1:1 with the `TabCommand` surface) rather than one `move_by(delta)`.
- **No config keys** for tab-bar scroll speed or min card width (constants until a user need exists).
- **Manual-only ceilings**: rejected-close survival is not reachable from the normal tab-bar UI (the bar routes `Close` on the tab's own connection), so it is covered by automated tests only; the Linux host has no screen reader for a11y steps.
- **Known flaky test (pre-existing, unrelated)**: `sandbox_terminated_and_unterminated_overflow_are_bounded_and_reaped` can fail under parallel full-gate runs with `Text file busy (os error 26)` from fixture-spawn contention; passes solo and on rerun.
