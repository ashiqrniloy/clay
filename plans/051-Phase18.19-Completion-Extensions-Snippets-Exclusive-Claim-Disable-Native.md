# Phase 18.19: Completion Extensions: Snippets, Exclusive Claim, Disable-Native

## Objectives

- Extend the Phase 18.11 completion framework with a snippet item kind carrying LSP snippet syntax (tabstops, placeholders, choices) as inert text the client expands locally, with no provider code on accept.
- Add an opt-in `exclusive` claim on `CompletionProviderMeta` so a provider can replace (not merge with) lower-priority providers for a request; default remains priority-merge across providers.
- Add a `serverDisableCompletion` Clay JS API so users turn off the native/base provider (or any provider/package) from `~/.config/clay/init.js` instead of packages silently self-promoting.
- Ship a small first-party snippet set per language (Rust `fn`/`match`/`impl`, TypeScript `interface`/`type`) to validate the snippet kind end-to-end through the existing package/provider path.
- Preserve every Phase 18.11 authority/performance boundary: completion stays server-side UI-reactive/cancellable, snippet expansion is a bounded client-local Rust text op, no client-side JavaScript, no hot-path blocking, no new permissions or authority.

## Expected Outcome

- `CompletionItem` carries a `text_format` (plain text vs snippet); snippet `insert_text` is expanded by a bounded Rust parser in the client on accept, entering a snippet session for Tab/Shift-Tab placeholder navigation.
- `CompletionProviderMeta` carries an opt-in `exclusive: bool`; when an exclusive provider is the highest-priority match for a request, lower-priority providers are suppressed for that request. Default priority-merge behavior is unchanged.
- Users can disable any completion provider or package prefix from `init.js` via `clay.completion.serverDisableCompletion`; disabled providers disappear from trigger listings and in-flight results are stale-dropped via a generation bump.
- Rust and TypeScript first-party packages ship snippet providers that prove the snippet kind, exclusive claim, and disable-native paths end-to-end.
- Language packages and the future Phase 18.21 LSP bridge can express merge vs replace against the base provider without provider wars.
- All new/changed public surfaces have Markdown docs, `docs/index.md` links, generated registry entries, inventory coverage, and `cargo test` coverage gates.

## Compromises Made

1. **No backslash escapes in `parse_snippet`.** `$` inside snippet text is always a tabstop/placeholder marker; `\$` / `\\` escapes are not parsed. First-party snippets (`fn`, `match`, `impl`, `interface`, `type`) contain no literal dollar signs, so no escape syntax is needed. Upgrade: add backslash-escape support in `parse_snippet` when a snippet provider requires literal `$` in insertion text. `ponytail:` comment marks the ceiling in `src/editor/snippet.rs`.
2. **No variable expansion (`$name` / `${name}`).** LSP snippet variables (`$TM_FILENAME`, `${CLIPBOARD}`, etc.) are rejected as `SnippetParseError::UnsupportedVariable`. They require server-side context or clipboard access, violating the client-local, authority-free snippet boundary. Upgrade: add opt-in server-side variable expansion with explicit permissions and an approved decision log when a concrete use case arrives.
3. **No nested placeholders inside defaults.** `${1:outer ${2:inner}}` is not parsed; the parser treats nested `$` inside defaults as unsupported variables. No first-party snippet uses nesting. Upgrade: add recursive parsing when a concrete snippet needs it.
4. **No mirror transforms (same placeholder appearing multiple times).** Each `$N` appears once; multiple occurrences of the same tabstop index are not synchronized. Upgrade: add mirror-transform support to `SnippetPlaceholder` and the session when needed.
5. **No `serverEnableCompletion` API in Phase 18.19.** Re-enabling disabled providers requires a package reload or runtime restart, both of which compose with the existing generation-based stale-drop. A dedicated enable op adds API surface for a workflow that existing primitives already cover. Add when package-reload-only re-enabling becomes a measurable friction point.
6. **Exclusive claim is provider-level, not mode-scoped.** An exclusive provider at the highest priority tier suppresses lower-priority matches for every trigger it matches, across all modes. Mode-scoped exclusivity ("this provider is exclusive only for Rust documents") is not modeled. Upgrade: add a `modes: Option<Vec<String>>` scope field on `CompletionProviderMeta` when per-mode exclusivity is needed.
7. **Snippet expansion is client-local Rust only; no provider code, no JS, no IPC on accept.** This keeps the Phase 18.11 authority boundary intact (items are inert text-replacement data). A future server-side pre-expansion step (e.g. variable resolution) would need a separate primitive and permission.
8. **Tab key is shared between menu activation and snippet navigation.** When a `SnippetSession` is active, Tab moves to the next placeholder instead of activating the current completion menu selection. This means Tab cannot both accept a completion and navigate its snippet in one keystroke; the accept happens on Enter (or click/highlight + commit character), then Tab navigates the installed session. Upgrade: not anticipated; this is the standard LSP completion behavior.
