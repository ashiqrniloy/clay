# Phase 18.9: Generic Text/Code Modes, Key Behavior, and Mode Discovery Fallbacks

## Objectives
- Install durable, always-available `core.text` and `core.code` fallback major modes so any file opens into a predictable, editable mode even when no language package is installed, disabled, or invalid.
- Extend server-owned document classification with extension, exact-filename, MIME hint, shebang, and bounded leading-content probes, with deterministic fallback precedence.
- Expose generic key/text behavior (`Tab`, `Enter`, indentation, pair insertion, comment continuation hooks, electric characters, and fallback command routing) through inert behavior manifests executed by Rust-known transform engines only.
- Add mode discovery/listing commands (including "why a document selected its active mode or fallback") for Control Center and package diagnostics.
- Preserve all Phase 18.7/18.8 authority, hot-path, and performance invariants: no synchronous JavaScript before local paint, no client-side package JavaScript, no new filesystem/network/shell/AI/WASM/raw-op/native-widget/client-JS/package-manager authority.

## Expected Outcome
- Any file opens into a deterministic text/code mode with documented fallback behavior; missing/disabled/invalid language packages never block open or edit.
- `Tab`/`Enter` and other generic key behaviors are exposed as reusable `TextTransform`/`KeyRoutingOverride` primitive data that language packages can reuse later.
- Document classification precedence is deterministic and observable: user override > package-declared pattern > shebang/content hint > `core.code` > `core.text`.
- Mode discovery commands list active mode, package provenance, and the fallback rationale, usable from Control Center and package diagnostics.
- Language packages can add capabilities incrementally without becoming required for basic editing.
- No Markdown-specific, Python-specific, or any language-specific Rust branches are added; all generic behavior lives behind reusable primitives.

## Entry Gate

- Do not start until Phase 18.8 command execution and transient menu routing are available for user-visible mode/help/discovery commands (`plans/036-Phase18.8-Bottom-Pane-Transient-Menu-and-Command-Execution-Foundation.md`).
- Do not start until Phase 18.7 persistent runtime, generic package/mode activation path, and removal of the Markdown-specific open-time Rust branch are verified (`plans/031-Phase18.7-Persistent-Server-Runtime-and-JS-ParseHandler-Bridge.md`).
- This phase is a fallback/mode-foundation gate, not an incremental mode-feature phase: `core.text`/`core.code`, classification precedence, generic key behavior, and discovery commands ship as one coherent, security-reviewed unit with their own plan, primitive review, decision log, and dedicated tests.
