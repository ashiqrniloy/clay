# Phase 24.1: Transient Menu Interaction Round-Trip

Prerequisite: Plan 079 (Phase 22.8 — Per-Tab Workspace and Document Isolation) and Plan 080 (Configuration Modular Structure) complete — both verified with zero unchecked tasks on 2026-08-11.

This plan implements the missing primitive that `roadmap.md` Phase 24 depends on: a **server-authoritative interaction round-trip for transient menus**. Today every interactive menu session (`completion`, tab-close confirm, document-switch) is client-owned: the client allocates session ids, mutates query/selection locally, and activates locally. The Command Centre (`src/server/control_center.rs`) is server-owned and tested but unreachable — no protocol messages carry menu query/selection/activate/cancel intents, and no server→client snapshot push exists.

Scope boundary: Phase 24.1 ships **generic menu round-trip plumbing** (protocol wire types, server session store, client keystroke routing for server-owned sessions, lifecycle) proven end-to-end by minimally wiring the existing `ControlCenter` as the first server-owned session kind. It explicitly does NOT ship: the command-mode keybinding/default-chord and `shell.client*` inclusion (Phase 24.2), the fuzzy matcher (Phase 24.2 — existing substring filter ships as-is), path mode (Phase 24.3), the centered/scrim surface (Phase 24.4 — menus keep their current bottom `CommandPalette` anchor), or sequence keybindings (Phase 24.5).

Confirmed decisions (decision log `2026-08-11-1711-command-centre-...`):
- Menu sessions are server-owned and interactive via protocol round-trip; the client renders snapshots and forwards keystrokes while a modal session is active.
- One shared `TransientMenuSession`-based surface hosts all session kinds; new kinds plug into the round-trip, no new overlay systems.
- Local client-owned sessions (completion, tab-close confirm, document-switch) stay client-owned — they require client-local edit authority and sub-millisecond feedback; the round-trip is additive, not a migration.

What ALREADY works and must be preserved (verified against code):
- Client-local menu keyboard interaction: `route_menu_key` (`src/masonry_pane_document.rs:2066+`) consumes ArrowUp/Down (selection), Enter/Tab (activate), Escape (cancel), and completion commit characters, re-syncing the overlay through `EditorAction::MenuStateChanged`.
- Menu push path: pane view `PaneMenuSync` (session copy + pending tri-state + connection-shared id allocator, `src/masonry_pane_document.rs:195-240`) → driver `apply_menu_sync` (`src/main.rs:183-200`) → `EditorWidget::set_active_menu` + `sync_overlays` → `PackageOverlayHost` rendering via `TransientPackageOverlay::from_menu_session` (`z.overlay`, origin→anchor). Menus are per-tab chrome state.
- `TransientMenuSession` typed state (`src/shell/transient_menu.rs`): prompt/query/items/selection/status/focus policy/origin, bounded by `TRANSIENT_MENU_MAX_*` constants (`src/perf/budgets.rs:219-223`).
- `ControlCenter` (`src/server/control_center.rs`): lists registry + built-in commands, filters by query, executes through `CommandExecutor`; fully unit-tested; marked `#![allow(dead_code)]`.
- Command execution path: `ClientMessage::CommandIntent` → `execute_command_intent` (`src/server/connection.rs`); `controlCenter.open` currently returns bare `Accepted`.
- Protocol codec: rkyv `Archive`/`Deserialize`/`Serialize` on `ClientMessage`/`ServerMessage` with 1 MiB frame cap (`src/protocol/codec.rs`); large `ServerMessage` variants are boxed to keep the union floor small (`src/protocol/mod.rs:1305`).

Entry gate: `plans/079-...md` and `plans/080-...md` have zero unchecked tasks (verified 2026-08-11).

## Objectives

- Any server-owned `TransientMenuSession` is fully interactive end-to-end: open, type to filter, move selection, activate, cancel — with the server authoritative for query, items, and selection.
- The round-trip is generic: a server session-kind registry (`ControlCenter` first) so Phase 24.3 path mode plugs in without new protocol.
- Existing client-owned sessions (completion, tab-close, document-switch) behave exactly as before; no regression in their latency or authority.
- Payloads stay bounded by the existing `TRANSIENT_MENU_MAX_*` constants; the new wire types are rkyv-archived and the `ServerMessage` union floor does not grow (boxed variant).
- Server menu authority cannot be reached by package code: sessions open only through built-in command execution; packages keep the existing inert overlay contribution path.

## Expected Outcome

- Executing `controlCenter.open` (via command intent) opens the Control Center as a live menu: typing filters the command list (server-side substring filter), arrows move selection, Enter executes the selected command through `CommandExecutor`, Escape closes.
- Session lifecycle is robust: tab switch, disconnect, session replacement, and duplicate/stale ids are handled; sessions sweep on connection close.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`.
