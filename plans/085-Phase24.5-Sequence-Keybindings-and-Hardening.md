Scope boundary: this phase is the Command Centre hardening phase. It extends the client keybinding router from single-stroke matching to multi-stroke sequences (Emacs-style chords), assigns chord defaults for command and path mode, extends conflict/ambiguity validation to sequence prefixes, adds performance budgets and guards for the Command Centre round-trip, and runs an authority review confirming the built-in browse grant cannot be reached by package code. It does **not** add a new editor mode, language mode, first-party JS package, UI component, overlay anchor, theme token, or package runtime capability. The Command Centre surface, scrim, centered origin, transient-menu round-trip, command execution mode, path mode, and fuzzy matcher are all implemented in Plans 081–084 and are reused unchanged. Multi-stroke support changes the router and the `bindKey`/`unbindKey` chord-string format only; it adds no new protocol message, snapshot field, op, or package authority.

Approved decision source: `decision-logs/2026-08-11-1711-command-centre-surface-path-mode-and-sequence-keybindings.md` (user explicitly approved extending `route_key` to sequences with pending-chord state, timeout, and cancel-on-mismatch).

## Objectives

- Extend `route_key` (`src/client/behavior.rs`) and the `bindKey`/`unbindKey` chord parser (`src/server/ops/keybindings.rs`) from single-stroke to multi-stroke sequences, so Emacs-style chords (e.g. `Ctrl+X Ctrl+P`) are bindable through the existing keybinding system and `init.js`.
- Hold pending-chord state (accumulated strokes + start instant) outside the immutable router so a mismatch or timeout cancels cleanly without leaking a prefix into the editor text path.
- Extend manifest conflict/ambiguity validation to sequence prefixes so a single-stroke binding that is a strict prefix of a multi-stroke binding in the same context is rejected (ambiguous), and two rules sharing a non-leaf prefix are reported.
- Replace the temporary single-stroke defaults for `controlCenter.open` and `controlCenter.openPath` with chord defaults, without changing the command IDs or routing policies.
- Add CI-guarded performance budgets for Command Centre menu open latency, per-keystroke filter updates, and listing snapshot sizes, and an authority review proving the built-in browse grant stays unreachable from package code.
- Keep protocol compatibility, primitive reference docs, the generated registry, the example configuration, the manual test plan, and the code wiki current.

## Expected Outcome

- Multi-stroke keybindings work everywhere keybindings do: typing a chord prefix holds pending state, the next key either completes the chord (dispatching through the existing `RoutedBehavior` path) or cancels (the unmatched key is re-evaluated as a fresh keystroke); a configurable timeout cancels a stale pending chord; a mismatched key never inserts text into the document while a chord is pending.
- `bindKey("Ctrl+X Ctrl+P", "controlCenter.open")` and the equivalent table form install and unbind multi-stroke rules; `parse_key_chord` is generalized to `parse_key_sequence` and accepts space-separated stroke lists.
- Manifest validation rejects an ambiguous prefix collision (e.g. `Ctrl+X` and `Ctrl+X Ctrl+S` in the same context) and accepts unambiguous chords; the error names the colliding command.
- The Command Centre opens via chord defaults; command and path mode behavior, fuzzy scoring, centered surface, scrim, accessibility, and package denial are unchanged from Plans 081–084.
- Performance budgets for menu open latency, per-keystroke filter updates, and listing snapshot sizes are pinned as advisory constants with deterministic structural guards (no hard wall-clock threshold before stable CI evidence, per the Phase 21 promotion rule); the browse-grant authority review is recorded with regression tests.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, and `cargo bench --no-run`.
