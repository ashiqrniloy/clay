# Plan: Phase 18.15 — Text Vocabulary, Two-Axis Decorations, and Theme Registry

Implements `roadmap.md` Phase 18.15 and decision `decision-logs/2026-07-09-0352-tiered-tree-sitter-themable-syntax-vocabulary-theme-registry-and-opt-in-lsp.md` (component 2 vocabulary + component 3 two-axis decorations + component 4 theme registry). This phase is the rendering contract every later phase (18.16 engine, 18.17 diagnostics, 18.18–18.21 language work) emits and renders through.

Scope boundary: this phase adds the vocabulary, the two-axis decoration model, and the theme registry as single source of color. It does **not** add the tree-sitter engine (18.16), range diagnostics (18.17), or any language-specific behavior. Existing first-party packages must keep rendering through a compatibility mapping.

## Objectives

- Establish LSP-based token vocabulary (base `SemanticTokenType` + `SemanticTokenModifiers` + Clay prose extension) as the contract packages emit and themes bind to.
- Refactor `DecorationSpan` from a free-form `style_token: String` to a two-axis `token_type` + text-attribute `modifiers` model, with a compatibility mapping so current `style_token` families keep rendering.
- Introduce a `StyleRegistry` as the single source of editor/syntax color; migrate every hardcoded `Color` constant out of `src/editor/surface.rs` into the registry.
- Author the default Clay theme plus two shipped themes — **Gruvbox Material Dark** and **Gruvbox Material Light** — selectable from `~/.config/clay/init.js` via a documented `setTheme()` Clay JS API.

## Expected Outcome

- All editor and syntax color is read from the active theme's `StyleRegistry`; no hardcoded paint-color literals remain (`cargo test` source-guard enforces this).
- A markdown `**bold**` span emits `modifiers=bold` with no token-type color; a function name can carry `token_type=function` + `modifiers=bold|declaration` (two-axis coverage test).
- `setTheme("@clay/theme-gruvbox-material-dark")` and `...-light` work from `init.js`; switching themes visibly changes editor colors; disabling all themes still renders a valid default.
- Existing `@clay/rust`/`@clay/typescript`/`@clay/javascript`/`@clay/markdown` packages keep highlighting through the compatibility mapping, with no behavior regression.
- Full Linux validation gate passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, plus the Clay JS API inventory/registry/facade and primitives/smoke doc suites.

## Phase 18.16.5 Typography Handoff

- `StyleRegistry` remains the single source of editor/theme colors and text attributes; it does not own installed-font preferences or layout-affecting typography state.
- Phase 18.16.5 adds a separate typography registry/protocol revision and lets later vocabulary/style-map work carry semantic font roles without turning font choice into a color token.
