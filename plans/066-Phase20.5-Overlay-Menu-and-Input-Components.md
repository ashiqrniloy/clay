# Phase 20.5: Overlay, Menu, and Input Components

This plan implements `roadmap.md` Phase 20.5. It activates the reserved component kinds (`dropdown`, `collapse`, `modal`; `table` only if a real package need justifies it), adds the missing input/menu surfaces (pop-up/dialog, text input field, multi-select, context menu, menu bar, tooltip, command palette), and uplifts the existing transient menu and inline completion pop-up onto one shared overlay foundation — all token-driven, state-complete, keyboard-navigable, and accessible.

Scope boundary: Phase 20.5 owns overlay/menu/input component kinds and surfaces only. It does **not** restyle already-implemented kinds (Phase 20.4), change the shell layout model (Phase 20.3), segregate theme packages or ship settings UI (Phase 20.6), add conformance guardrails beyond component validation tests (Phase 20.7), or change any existing `ComponentKind`, typed style variable, `ThemeTokenType`, or core/package token name. New kinds and any new style variables are additive-only. All actions remain inert command intents; all styling remains token-only.

Entry gate: Phase 20.4 (`plans/065-...md`) must have zero unchecked tasks. Load the complete mandatory project-local UI skill stack before implementation. Load the `clay-ui` skill and read `.agents/skills/clay-ui/references/components.md` and `references/tokens.md`.

## Objectives

- Activate reserved kinds `dropdown`, `collapse`, and `modal` in `ComponentKind` (move them out of `DeferredComponentKind` in `src/shell/components.rs`) with validation, style variables, docs, and tests. Evaluate `table` against a real package need; keep it reserved with a recorded rationale if none exists.
- Add new package-facing components: pop-up/dialog, text input field (focus, placeholder, validation states), multi-select (dropdown variant with badges), context menu, menu bar, tooltip, and a command palette surface for the Command Centre direction.
- Uplift the transient menu (`src/shell/transient_menu.rs`) and inline completion pop-up (`completion_result_to_menu_session`) onto the shared overlay primitive (`overlay` kind + `portal` + `paint_tooltip_shell`): consistent anchoring, dismissal, focus policy, provenance display, and token styling.
- Consume the Phase 20.1 `z-level` tokens (`z.overlay`/`z.modal`/`z.tooltip`) for overlay stacking order.
- Complete keyboard navigation and accessibility roles for every new surface.
- Keep the catalog, package authoring guide, and component validation tests current.

## Expected Outcome

- Pop-ups, dropdowns, text inputs, multi-selects, menus, tooltips, the command palette, and the completion pop-up share one overlay foundation and one aesthetic.
- Package authors gain the new components through documented, validated kinds only; reserved-kind validation now accepts `dropdown`/`collapse`/`modal` and rejects misuse with clear errors.
- Every new surface is token-driven (no raw colors/CSS), state-complete (`Rest`/`Hover`/`Active`/`Focus`/`Disabled`), keyboard-navigable, and has an accessibility role.
- The transient menu and completion pop-up render through the shared overlay primitive with consistent anchoring, dismissal, and focus policy.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`.
