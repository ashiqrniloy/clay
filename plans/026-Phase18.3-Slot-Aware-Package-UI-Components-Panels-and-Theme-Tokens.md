# Phase 18.3: Slot-Aware Package UI Components, Panels, and Theme Tokens

## Objectives
- Promote Phase 18.3 package UI primitives from planned inventory rows into runtime-backed, slot-aware Clay package UI contribution APIs.
- Replace the temporary fixed-sidebar SDUI assumption with package-declared fixed panels and transient overlays composed through Clay-owned `PaneSlotLayout` geometry.
- Define and implement the first stable Clay component catalog for package authors while preserving inert component state, registered command/action intents, and native-client ownership of Masonry widgets.
- Add typed package theme token declarations and internal theme-token resolution so component styling no longer depends on hardcoded SDUI color/size constants or raw CSS-like package input.
- Keep user/package layout overrides, package UI state scopes, and shell configuration APIs either fully documented if implemented or explicitly deferred to Phase 18.4.
- Update package authoring docs, Clay JS API docs/registry, primitive docs, package validation, structural UI tests, performance guards, and code wiki coverage for the implemented slot-aware UI model.

## Expected Outcome
- Packages can register inert, package-prefixed fixed panel, component tree, transient overlay, and semantic theme token declarations through documented `clay:ui` APIs.
- Clay validates package UI contributions for slot targets, component IDs, action targets, package prefixes, permissions, payload budgets, theme tokens, accessibility/focus policy, and prohibited authorities before client publication.
- The native client renders fixed slot panels and transient overlays using Clay-owned shell/slot/component state; no package JavaScript, raw CSS, raw ops, direct Masonry widgets, native handles, or renderer callbacks enter Masonry hot paths.
- Existing `clay:sdui` panel/status behavior remains compatible or is bridged through the new slot-aware contribution model with explicit migration/status docs.
- Package-authored Markdown preview/status UI can consume generic `PanelContribution`, `ComponentContribution`, `TransientOverlayContribution`, and `PackageThemeTokenDeclaration` primitives later without Markdown-specific Rust shell branches.
