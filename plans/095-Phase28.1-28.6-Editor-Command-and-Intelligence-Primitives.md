## Objectives

- One chord parser: package `keyRouting` / keymap JSON uses
  `parse_key_sequence`, so `Ctrl+Shift+M` and sequences become real
  `KeyStroke`s.
- One comment-toggle engine and one line-prefix transform engine, both
  manifest-driven; inert package commands become aliases or are rejected.
- FoldingRange is a real primitive: protocol + budgeted publish + tree-sitter
  computation + client-local collapse in the existing gutter.
- `DecorationKind::Link` carries a target; hover/click is one generic
  decoration-intent path (markdown now, LSP go-to-def later).
- `DecorationKind::InlayHint` renders rust-analyzer hints through the
  decoration pipeline and the Phase 27.5 `createLspBridge` factory.
- Buffer-word (and later provider) ranking uses one shared scorer inside the
  existing candidate scan.

## Expected Outcome

- Markdown default keymaps (`togglePreview`, `insertHeading`, `toggleList`)
  and code-mode comment toggle work from the keyboard after one-line
  `loadPackage`.
- `editor.toggleComment` / list / heading commands mutate the buffer; the
  command palette has no metadata-only command for those IDs.
- Code files fold on multi-line tree-sitter nodes; gutter chevrons and
  `editor.clientToggleFold` toggle client-local collapse.
- Markdown links are underlined, hoverable, and activatable without minting
  grants; HTTP targets display only (no network).
- rust-analyzer inlay hints paint as decorations and can be toggled.
- Completions rank by exact-prefix / case / length / recency, not `BTreeSet`
  alphabetical order.
- `PROTOCOL_VERSION` bumps only when wire types change (22 before 28.6;
  23 after its bounded recency field).
- New public surfaces have Clay JS APIs, `examples/init.js` lines, test-plan
  steps, and wiki pages. Phase 28.7 still owns the mass `js_runtime` test
  move and the final CI budget promotion.
