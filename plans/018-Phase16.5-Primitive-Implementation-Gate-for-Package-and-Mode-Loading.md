# Phase 16.5: Primitive Implementation Gate for Package and Mode Loading

## Objectives

- Implement the smallest runtime gate that turns the Phase 16 primitive architecture into validated package and mode loading inputs without starting full package installation.
- Add server-owned package manifest, permission, mode classification, mode activation, and command-registration primitives needed before Phase 17 package loading can safely expand.
- Preserve Clay's authority boundaries: packages declare inert primitives, server validation owns activation, and the Rust client receives only validated manifests, SDUI, or protocol data.
- Keep ordinary typing, paint, and text-event handlers free from package JavaScript, synchronous IPC, package validation, or package-manager work.

## Expected Outcome

- Clay can validate a Clay package metadata object/fixture containing package identity, `apiPrefix`, permissions, mode declarations, command declarations, and load/runtime entry metadata.
- Clay has a minimal server-side primitive gate for document classification, one-major-mode activation, package-prefixed command registration, and package-owned behavior-manifest contribution validation.
- Invalid package prefixes, duplicate prefixes, duplicate mode names, duplicate command IDs, unknown permissions, malformed mode patterns, and ambiguous package key bindings fail at load/validation time with actionable diagnostics.
- Planned Clay JS API inventory entries for package/mode primitives either become implemented facade calls or remain explicitly planned with tests proving no accidental public raw-op surface exists.
- Phase 17 can build package install/enable/load workflows on these validated primitives instead of re-deriving the security and primitive boundary.

    - Functional: A server-side validator accepts Clay package metadata with `name`, `version`, `clay.apiPrefix`, `clay.permissions`, `clay.modes`, `clay.entry`, and optional `clay.loadEntry`, and rejects malformed metadata with structured diagnostics including package name/version/prefix and failed rule.
