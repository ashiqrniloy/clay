# Phase 24.3: Path Mode — Dired-Style Filesystem Browsing

Prerequisite: Plan 082 (Phase 24.2 — Command Execution Mode) must be complete with zero unchecked tasks. Preserve its current working-tree implementation, including the existing shared fuzzy matcher (`src/shell/fuzzy.rs`), before executing this plan.

Scope boundary: this phase adds the server-owned path-browser session, user-authorized browse listing, keyboard navigation, file activation, current-tab workspace activation, and a temporary single-stroke default binding. It reuses the existing bottom-anchored transient-menu surface. Centered placement and scrim rendering remain Phase 24.4; sequence/chord routing and final Emacs-style defaults remain Phase 24.5. Native file/folder dialogs remain unchanged as fallback paths.

Decision source: `decision-logs/2026-08-11-1711-command-centre-surface-path-mode-and-sequence-keybindings.md`.

## Objectives

- Open a server-owned path-browser session seeded from the active pane document’s directory, then the bound tab workspace root, then the server cwd.
- Browse arbitrary user-selected filesystem directories through a bounded, depth-1, Clay-owned listing that never runs in paint/layout or package JavaScript.
- Provide dired-style keyboard behavior: fuzzy filter, directory descend, empty-filter Backspace ascend, direct path editing, primary file open, and secondary open-directory-as-current-tab-workspace.
- Convert ephemeral browse authority into an explicit `SingleFile` grant only when opening a file and a `Directory` root grant only when opening a workspace.
- Open files in the active pane of the current tab, preserving duplicate-open focus routing and per-tab workspace/document isolation.

## Expected Outcome

- A default, user-rebindable single-stroke command (`controlCenter.openPath`, temporarily `Ctrl+Alt+P` until Phase 24.5 assigns sequence defaults) opens path mode in the active tab.
- The displayed path input starts at the active document’s canonical parent directory when available; otherwise it uses the tab root or cwd.
- Typing fuzzy-filters the installed directory snapshot; directory activation descends, empty-filter Backspace ascends, and direct absolute/relative path edits jump after server canonicalization.
- Enter on a file closes the menu and opens it in the active pane; opening an already-open file focuses its existing pane.
- Enter on a directory descends; `Alt+Enter` opens that directory as the current tab’s workspace through the existing tab registry binding and pushes reconciled tab/file-browser state.
- Linux blocking checks pass: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, relevant tests, `cargo test --all-targets`, and `cargo bench --no-run`.

## Compromises Made

- **Temporary default chord**: `controlCenter.openPath` ships with a Global `Ctrl+Alt+P` single-stroke default instead of Emacs-style sequences; Phase 24.5 owns sequence key routing and will replace the default without changing the command id. The chord is fully rebindable/removable via `bindKey`/`unbindKey` today.
- **Secondary activation is fixed**: `Alt+Enter` (workspace open) is not configurable in 24.3; generalized sequence/key-conflict hardening belongs to Phase 24.5. Every other Alt-chord falls through to the editor.
- **Client-side backspace mirror approximation**: the client pops its mirrored `server_query_buffer` locally before sending `MenuBackspace`; a stale mirror from a server ascend self-corrects on the next `TransientMenuSnapshot` resync. Accepted as the only approximate path (sequential server processing makes out-of-order relists impossible, so no epoch stamping was needed).
- **One active session per connection**: opening the Path Browser replaces any open Control Center (and vice versa), consistent with the Phase 24.1 store invariant; no concurrent menu stacking was built.
- **Sticky errors are sticky**: a failed listing sets a status that suppresses items and activation until the user edits the path; FilterOnly edits deliberately do not clear it (a clear-on-edit assumption was corrected during task 5 testing).
- **No new budget constants**: listings reuse `TRANSIENT_MENU_MAX_ITEMS` (256) and `TRANSIENT_MENU_MAX_QUERY_CHARS` (256); the depth-1 entry cap makes the non-abortable `spawn_blocking` traversal bounded by construction.
- **Built-in browse grant is the exception**: the path session acts as its own authorization event (no capability token), unlike native dialogs; it is the one Clay-owned exception and packages get no equivalent authority (codified in `authority-boundaries.md`).
- **Pre-existing flake hardened**: `tests/runtime_sandbox_harness.rs` reaping test's 1s wall-clock bound was load-sensitive; relaxed to 1500 ms (redundant with the `PayloadTooLarge` variant discrimination) after investigation.
- **Catalogue count drift fixed in docs**: the built-in command table grew 21 → 22 with `controlCenter.openPath`; no test asserted the count, so the drift was silent and corrected in wiki/test-plan docs during task 18.
