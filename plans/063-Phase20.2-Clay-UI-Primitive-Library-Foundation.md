# Phase 20.2: Clay UI Primitive Library Foundation

This plan implements `roadmap.md` Phase 20.2. It builds the Clay-owned native chrome primitive layer that every current paint path (core and package-contributed) composes from, so external packages cannot diverge from the Phase 20.1 design language.

Scope boundary: Phase 20.2 ships **native shell paint primitives** (Rust, client-side, `pub(crate)`) and routes existing one-off paint through them. It does **not** add package-facing `ComponentKind` entries, restyle components, add resize/drag behavior, or ship overlay/menu/input components — those remain Phase 20.3 (layout primitives), Phase 20.4 (component uplift), and Phase 20.5 (overlay/menu/input). New package-facing component kinds are explicitly out of scope.

UI skill selection recorded for this phase (use the current project UI skill requirements before implementation):

- `leonxlnx/minimalist-skill` (`minimalist-ui`): aesthetic continuity with Phase 20.1 — hairline `1px`-equivalent borders (`border.hairline`), near-invisible elevation, scarce accent, `kbd` keystroke micro-UI specs, muted-pastel badge/tag treatment, crisp small radii.
- `jakubkrehel/make-interfaces-feel-better`: craft details for state-complete primitives — concentric border radius (outer = inner + padding), optical over geometric alignment, scale-on-press (0.96) for interactive chrome, shadows-over-borders translated to Clay's near-invisible `elevation` tokens, interruptible state transitions via `motion` tokens.

Clay translation: these web-oriented skills inform native Masonry/Vello/Parley paint and token semantics only. Clay has no CSS/Tailwind, no browser, no `box-shadow`; web guidance maps to Clay theme tokens (`border.*`, `elevation.*`, `motion.*`, `radius.*`, `spacing.*`), `UiTextVariant` typography, and Masonry `Scene` paint primitives. Packages receive no renderer access; the catalog in `.agents/skills/clay-ui/references/` remains authoritative.

## Objectives

- Implement a small, documented set of native shell chrome primitives: divider/separator, focus ring, panel chrome (title row, collapse affordance, resize handle chrome), scroll chrome, badge/tag, `kbd` hint, icon slot, and tooltip shell.
- Make every primitive token-driven (no raw colors, spacing, radii, or sizes), state-complete (`hover`/`active`/`focus`/`disabled` where interactive), and accessibility-role-carrying.
- Route existing one-off chrome paint (`src/masonry_sdui.rs` SDUI chrome, `src/editor/surface.rs` editor chrome, status bar, package panel/overlay chrome, transient-menu chrome) through the new primitives.
- Enforce a conformance contract: primitives are the only way to paint UI chrome; package-declared components map onto primitives by construction through the SDUI paint path.
- Add structural tests proving primitives consume tokens (no raw values) and render all interaction states.
- Keep the clay-ui catalog, package authoring guide, primitive reference docs, Clay JS API docs/registry, and code wiki synchronized.
- Preserve current theme packages, component kinds, style-variable names, server/client authority, accessibility geometry, and hot-path behavior with zero breaking changes.

## Expected Outcome

- A small, documented native primitive set underpins every current shell/SDUI/editor chrome surface.
- No remaining hardcoded colors, spacing, or sizes in shell/SDUI chrome paint paths; the Phase 18.15/20.1 "single source of color/size" invariant extends from editor paint to all UI chrome.
- Package components continue to compose through existing `ComponentKind` kinds; they map onto primitives by construction because the SDUI paint path calls the primitive functions.
- Existing first-party packages (`@clay/markdown`, `@clay/git`, `@clay/rust`, `@clay/typescript`, `@clay/javascript`, LSP bridges, Gruvbox themes) render unchanged without manifest or style-variable edits.
- Ordinary typing, paint, layout, pointer, scroll, keypress, and text-event paths perform no package JavaScript, server round trip, theme re-resolution, filesystem/network work, or raw-op calls; primitives read cached resolved token values only.
- Linux blocking validation passes: `cargo fmt --check`, `cargo check --all-targets`, `cargo clippy --all-targets -- -D warnings`, and `cargo test --all-targets`.
