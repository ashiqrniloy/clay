# Phase 18.5: Replan Markdown End-User Loading After Shell/Layout Work

## Objectives
- Replan Markdown end-user loading so it consumes generic shell/package UI primitives from Phases 18.1–18.4 instead of driving architecture from fixture-only behavior.
- Fill concrete implementation gaps carried forward from Phases 18.1–18.4: the unchecked Phase 18.4 configuration API audit, the unimplemented generic `loadPackage` primitive, and the missing manual GUI smoke for the Markdown end-user path.
- Remove Markdown-specific UI assumptions and replace them with generic `clay:ui` contributions: no default side panel, optional preview/status as a package `PanelContribution`, main editor placement through the mandatory `main` slot, and fixed/transient panel choices through the generic shell.
- Update `plans/023-Phase20-Markdown-Mode-End-User-Loading-and-UI-Cleanup.md`, the Markdown package, package docs, authoring guide, tests, roadmap follow-ups, and wiki to reflect the implemented shell/package UI architecture.
- Preserve the explicit one-line package loading convention and the separate explicit `bindKey("Ctrl+O", "clay.documents.clientOpenFileDialog", { scope: "editor" })` user configuration.

## Expected Outcome
- `plans/023-Phase20-Markdown-Mode-End-User-Loading-and-UI-Cleanup.md` is updated or superseded so that every Markdown task references generic shell/package primitives rather than fixture-specific UI assumptions.
- The Markdown package default load path uses implemented generic primitives without requiring copied smoke fixtures, inline package manifests, or manual primitive registration in `init.js`.
- No default Markdown side panel is published on load; an optional Markdown preview is a package-owned `clay:ui` `PanelContribution` targeting a Clay slot (e.g., `right`) rather than a hard-coded left-sidebar fixture.
- The generic one-line package loading primitive (`loadPackage` or an equivalent documented resolver/loader) is either implemented or its gap is explicitly documented with a decision-log-backed temporary fallback.
- The Phase 18.4 configuration API audit gap is closed: all configuration surfaces (`setPackageOption`, `serverSetLayoutOverride`, and any Markdown-relevant options) have full Markdown docs, `docs/index.md` links, generated registry coverage, lookup metadata, `custom_properties`, and deterministic tests.
- Manual smoke instructions are updated for the actual end-user path: a Windows 11 developer can run `cargo run` with a minimal `~/.config/clay/init.js` that loads Markdown defaults and binds `Ctrl+O`, then open a `.md` file and see editor-only Markdown behavior/decorations.

The deferral and its rationale are recorded in `decision-logs/2026-06-15-1015-defer-generic-loadpackage-first-party-resolver.md`. The task shipped the package-owned `markdownLoadMode()` fallback entry that imports Clay facades directly without copied manifests.
  3. **Manual GUI smoke**: `cargo run -- smoke-gui` and fixture-specific smoke variants were not observed in the non-interactive agent session, consistent with Phases 18.2–18.4. This remains a developer handoff and is accepted as a Phase 18.5 task (task 10).
