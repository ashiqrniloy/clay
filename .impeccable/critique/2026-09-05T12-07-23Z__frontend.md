# Clay UI/UX Review — Architecture Wiring + Design Audit

Method: ⚠️ DEGRADED: single-context (no sub-agent tool exposed in this session)
Target: frontend (React/Tauri client) + design-system packages; evidence via dev fixtures + headless Chromium screenshots.

## Part 1 — Style/theme wiring verdict

### What is wired correctly
- Full inert-data pipeline: `clay.contributions.uiDesignSystem` (packages/design-neobrutal, design-glass) → Rust validation/resolution (`ActiveDesignSystem`, src/shell/design_system.rs; `apply_design_system`, src/server/ops/theme.rs) → snapshot → `designSystemStore` → `--clay-ds-*` CSS custom properties (frontend/src/theme/design-system-adapter.ts) → CSS modules with typed fallbacks. Colors are theme color-roles only, validated both in Rust and in the adapter (`VALID_THEME_COLOR_ROLES`). No package JS in paint paths.
- Config-driven activation exists: `preferences.json` `designSystem` applied at load (src/server/js_runtime/tests.rs `persisted_preferences_design_system_applied`), plus `theme.setDesignSystem` JS API.
- Components-first: real component library (frontend/src/components) consumed by views; SDUI renderer maps catalog kinds; conformance tests prove DOM continuity across live switches and clean revocation.

### Wiring gaps (why switching feels inconsistent)
1. **No user-facing style switch.** SettingsPanel.tsx exposes Theme/Appearance/Typography only; no design-system dropdown; `packages/settings` has no `settings.setDesignSystem` command; no command-centre entry. Style is config-file-only. Theme list is a hardcoded const in SettingsPanel.tsx, not derived from installed packages.
2. **Partial recipe coverage.** Neither DS package ships recipes for shell header, tab bar, status bar, file browser, pane separators, settings panel, chat internals, editor chrome, command-centre internals. Those surfaces read host fallbacks only → identical under every style. Switching styles visibly restyles only catalog controls (button/textInput/dropdown/list/collapse/modal/panel/badge/kbd).
3. **Silent slot drift / dead config.** Packages ship `tab.default.root.*`; tab-bar.module.css consumes `--clay-ds-tab-default-item-*` → tab recipes are no-ops. `tabBar.default.root.rest` unconsumed. textInput focus recipes (outline*) are dead because text-field.module.css sets `outline: none` on focus (border-color only). tokens.css defines 30 fallback vars no CSS consumes, including checkbox/switch/slider/table/tree/progress — components that do not exist in the React client. Legacy alias chains (list row/item, modal dialog/surface, textInput input/root) triple-nest fallbacks.
4. **Hardcoded bypasses escape the recipe layer:** tab-bar `.tabList` background; registry.module.css `.tabs/.tab/.tabStrip` (a second, differently-styled tab implementation); chat `.sessionList`/`.footerCommands`; these never change with the design system.
5. Settings "Appearance" is local useState("system"), never hydrated from persisted preferences.

### What's working
- Command Centre is the strongest surface: 2px border + hard 4px offset shadow read clearly; centered width discipline.
- Token discipline is real: zero literal colors in component CSS; a11y fallback layer (reduced motion/transparency, forced colors, global focus-visible) is production-grade.
- Component catalog is state-complete and reused by most views.

### Priority issues
- **P1 Style-switch coverage:** chrome surfaces ignore design systems → switching produces a half-styled app. Fix: extend DS recipes to shell/tabBar/statusBar/fileBrowser/settingsPanel/chat slots (or delete dead slots), and make tab-bar/registry/chat consume recipe vars.
- **P1 No runtime style selection + hardcoded theme list.** Fix: `settings.setDesignSystem` + dropdown listing enabled DS packages; themes enumerated from package service.
- **P1 Silent drift.** Fix: conformance test cross-checking (a) package recipe keys vs CSS-consumed `--clay-ds-*` names, (b) tokens.css fallbacks vs consumption, (c) recipe property keys vs CSS consumption (catches dead textInput focus outline).
- **P2 Neobrutal identity collapses on dark themes:** offset shadows use `border.strong` (#3d385c on #100f17) → invisible; 1px borders read as faint outlines; list rows go transparent → weaker than core baseline. Result: flat generic dark UI, not brutalism. Fix: 2px structural borders, ink-contrast shadow color role (e.g. text.primary-derived), solid list fills, bimodal density as the direction doc promises.
- **P2 Core baseline monotony:** button/input/trigger/rows share one gray fill; muted button ≈ invisible text; single purple accent; system-ui 13px default. Fix: differentiate control vs field vs row surfaces, give muted a ghost border, ship a real default UI font stack.
- **P2 textInput focus = border-color change only (`outline: none`)** — weaker than every other control; also kills DS focus recipes. Fix: consume focus outline vars like button does.
- **P3** `--clay-text-secondary` undefined (modal.module.css close button); chat action row double-framing (segmented 1px-gap cells + per-button neobrutal borders); scrim near-opaque black hides context.

### Persona red flags
- Alex (power user): cannot switch or even discover UI styles from the UI; no accelerator for appearance.
- Jordan (first-timer): muted buttons read as plain text; disabled vs muted hard to tell.
- Sam (a11y): text input focus relies on border color alone; otherwise focus handling is strong.
