# Prioritized Primitive Backlog and Phase 17 Prerequisite Checklist

This backlog turns the Phase 16 primitive analysis and Phase 18.1 shell/layout architecture gate into a sortable implementation queue for Phase 17 package/mode loading, Phase 18 Markdown mode POC work, and the Phase 18.2 through 18.4 shell/package UI sequence. Every entry traces to `docs/reference/primitives/registry.md` and at least one primitive analysis or strategy document. Phase 16.5's implemented validation bridge is documented in `docs/reference/primitives/implementation-gate.md`; Phase 18.1's shell/layout architecture gate is documented in `docs/reference/primitives/shell-layout-strategy.md` and `docs/wiki/modules/phase18.1-shell-layout-primitive-review.md`.

Priority tiers:

- **Phase-17-required**: must be implemented or stubbed by the Phase 17 package/mode foundation before Markdown work can safely begin.
- **Phase-18-required**: can be implemented in Phase 18, but Phase 17 must leave a compatible extension point or explicit handoff. Phase 18.10 adds `SyntaxGrammarContribution` as the generic package-provided Tree-sitter grammar primitive before grammar-only language packages.
- **Phase-18.2-shell-runtime**: native Clay shell, working-area, pane/split, and pane-slot runtime foundations required before slot-aware package UI can ship.
- **Phase-18.3-slot-ui**: package component, fixed panel, transient overlay, and theme-token contribution primitives required after the shell runtime exists.
- **Phase-18.4-state-config**: package UI state/data, layout override, input/action/configuration integration primitives required after slot-aware UI exists.
- **Phase-18.11-completion**: generic completion provider framework required after Phase 18.10 syntax/decoration plumbing and package provenance are complete, before Phase 19 hot reload and first-party language package expansion.
- **Deferred**: recorded for future modes/packages, not a Markdown POC readiness gate.

## Sorting and Handoff Notes

- Sort first by `Priority Tier`, then by `Plan Owner`, then by risk/permission-bearing status from `package-security.md`.
- Phase 17 should implement all `Phase-17-required` rows or explicitly document any exception before Phase 18 begins.
- Phase 18 should treat `DecorationRange` and `IncrementalParseUpdate` as required Markdown POC foundations; `FoldingRange` remains optional/stretch despite being listed in the Phase-18 tier for visibility.
- Phase 18.16 implements `SyntaxGrammarContribution` as a tiered engine before broader language-intelligence work: Tier 1 compiled first-party native descriptors, Tier 2 explicit web-tree-sitter WASM overrides, and Tier 3 server-side package-JS fallback. The primitive keeps active syntax grammar separate from active major mode, so packages can highlight `core.code`/`core.text` fallback documents without language-specific Rust branches.
- Phase 18.11 should implement `CompletionTriggerAndResult` after Phase 18.10 syntax/decoration plumbing and package provenance are complete. The primitive keeps trigger detection as inert manifest data, runs result computation on a cancellable server-side `UiReactivePriority` lane, reuses `TransientMenuSession` for display/acceptance, ships one built-in buffer-word provider, and keeps LSP/AI/workspace-index/shell/network providers as later add-ons requiring a future approved decision log and explicit permissions.
- Phase 18.20 implements `LanguageIntelligenceRequestAndResult` and `LanguageServerSession` as engine-neutral intelligence and deny-by-default process primitives. Phase 18.21 bridge packages remain pending and must integrate only through the documented LSP 3.17 → Clay mapping contract.
- Phase 18.2 now implements internal `WorkingAreaLayout`, `PaneSplitTree`, and `PaneSlotLayout` runtime foundations before Phase 18.3 package UI work, so future fixed/transient panels should build on Clay-owned slot geometry instead of the old fixed-sidebar geometry.
- Phase 18.3 implements `PanelContribution`, `ComponentContribution`, `TransientOverlayContribution`, and `PackageThemeTokenDeclaration` as generic package UI primitives before Markdown preview/status UI consumes them; the remaining API docs/registry and Phase 18.4 state/config surfaces must continue to preserve this generic contract.
- Phase 18.4 implements `PackageInputContribution`, `PackageUiStateScope`, `PackageLayoutOverride`, and the supported `PackageOwnedConfiguration` option contract through documented Clay JS APIs only; remaining direct shell mutation, durable persistence, pane selector, multi-panel ordering, overlay z-order, cross-window layout, and package enable/disable surfaces stay deferred.
- Deferred rows remain registry obligations but should not block Markdown mode unless the Phase 18 scope expands.
