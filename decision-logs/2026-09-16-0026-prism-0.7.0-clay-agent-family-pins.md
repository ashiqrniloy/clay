# Decision: Prism 0.7.0 clay-agent family pin set; unknown agent events drop instead of faking Started

## Decision

`clay-agent` moves its live Prism pins from exact `0.5.5` to exact `0.7.0`
for the same seven adopted families — `@arnilo/prism`,
`@arnilo/prism-core`, `@arnilo/prism-providers`,
`@arnilo/prism-coding-tools`, `@arnilo/prism-web-tools`,
`@arnilo/prism-memory`, `@arnilo/prism-mcp` — keeping direct
`better-sqlite3@13.0.3` and moving `playwright-core` from exact `1.61.0` to
exact `1.63.0`. On the same cut, the clay-agent runtime floor moves from
Node `>=20` to Node `>=22` (`MIN_NODE`, `engines.node`, README, wiki), and
the Rust event mapper’s catch-all is removed: an unknown Prism
`AgentEvent.type` returns `None` (dropped, not forwarded) instead of
synthesizing `AgentWireEvent::Started`. The 0.7 opt-ins (attention
compiler, memory fabric, work scopes, host-owned spawn tools) are adopted
only through the four-cut sequence in plans 120–123; office/OCR, ACP,
AG-UI-in-daemon, E2B, realtime voice, Bedrock Converse, and model-router
facades stay out of clay-agent. Rollback for Clay is re-pinning exact
`0.5.5` + `npm ci` (Clay never shipped `0.5.6` or `0.6.0`).

## Context

Prism 0.7.0 (“Host Completeness, Evidence, and Capability Boundaries”) is
the published successor to 0.6.0, which was the successor to 0.5.6 — a
release upstream never published. Clay has been live on exact `0.5.5`
since 2026-09-08 (plans 109/113 follow-ups) and therefore has never run
the 0.5.6 folded content, the 0.6.0 Node floor, or any 0.7 behavior; this
one pin jump absorbs two cuts.

What the jump carries that touches a host:

- **0.6.0 Node floor** — every publishable package declares
  `engines.node >= 22`; Node 20 is unsupported (upstream EOL 2026-04-30).
  Clay’s CI already runs Node 24, and the dev host is Node 24, so the
  floor is documentation plus `MIN_NODE`.
- **Third-party floors** — `playwright-core` optional exact peer
  `1.61.0` → `1.63.0` in `@arnilo/prism-web-tools` (Clay pins it
  directly for browser/Obscura work and must move with it);
  `@nanonets/graft` optional peer `^0.16.0` → `^0.16.0 || ^0.18.0` in
  `@arnilo/prism-memory/graft`. `pg` and office floors do not apply
  (Clay runs no Postgres session store and no office package).
- **0.7 hard refusals** — ACP `mcp.allow` matching is now strict
  WHATWG origin/path-subtree (clay-agent does not run `prism-acp-agent`),
  and `router.providerSource(model)` throws
  `ERR_PRISM_MODEL_ROUTER_ASYNC_REQUIRED` / `_ASYNC_STATE` when
  governance or durable state is configured (clay-agent does not call
  the router facade). Neither applies, and nothing persisted changes
  shape: 0.7 additions write through existing working/vector,
  checkpoint, and observational-memory stores under the same schema,
  and stores still fail closed on unknown newer schema versions.
- **0.7 opt-ins** — attention compiler (`AgentConfig` / `AgentDefinition`
  / `RunOptions` overlay plus `attention_compiled` telemetry), memory
  fabric, work scopes, and host-owned
  `createSpawnAgentTool`/`createWaitAgentTool`/`createCancelAgentTool`
  with `observeSupervisorLifecycle` bridging `delegation_*` to redacted
  `subagent_started` / `subagent_stopped`. These are the substance of
  plans 121–123.
- **Event-type growth** — the new lifecycle/telemetry types reach
  Clay’s `map_event` catch-all. That catch-all already caused one
  incident: `agent_suspended` fell through to `AgentWireEvent::Started`,
  the client believed a run was streaming forever, and the fix was an
  explicit arm (comment in `src/server/agent/run.rs`). The mapper still
  asserts a spurious `Started` for `provider_turn_finished` without
  usage. Adopting 0.7 without closing the catch-all would reopen that
  class of bug on `attention_compiled`, `subagent_started`,
  `subagent_stopped`, and `delegation_*`.

Plan 120 (`plans/120-Adopt-Prism-0.7.0-Pin-And-Event-Mapper.md`) owns
this cut and lists the decision log as its first task; plans 121–123 own
the opt-ins. The pin-set shape (seven families, exact versions,
`better-sqlite3@13.0.3`, explicit subpaths, no ACP/AG-UI/office in the
daemon) carries over unchanged from decisions `2026-09-06-0432` and
`2026-09-07-2149`.

## Alternatives Considered

1. **Stay on `0.5.5` until Phase 5/6 needs 0.7 features** — rejected.
   Clay is now two cuts behind and the gap only grows; the pin jump
   itself has no Clay-side hard work (no ACP, no router facade, no
   persisted-shape migration), and staying behind blocks attention,
   wiki ingest, and Phase 6 spawn.
2. **Bump only the families the current code imports** — rejected.
   Prism cuts are lockstep; a mixed 0.5.5/0.7.0 tree is exactly what the
   0.7 upgrade step 1 and the release gate refuse.
3. **Range pins (`^0.7.0`) or `npm update`-style floats** — rejected.
   Project pattern is exact reviewed pins for the seven adopted
   families; ranges would let a future patch change the host contract
   unreviewed.
4. **Keep `playwright-core@1.61.0` and accept the peer warning** —
   rejected. The pin is a deliberate exact peer in
   `@arnilo/prism-web-tools` because browser control is
   version-sensitive; Clay owns the browser binary and would be testing
   an unsupported pairing.
5. **Keep the catch-all mapping unknown events to `Started`** — rejected.
   It is a known-bad shape for this repo (told in the `agent_suspended`
   comment and still asserted for unreported `provider_turn_finished`),
   and 0.7 adds several event types that would hit it. Dropping unknown
   types is smaller than mapping each new type speculatively.
6. **Add `AgentWireEvent::Ignored` and forward drops to the client** —
   rejected. Extra wire traffic and frontend surface for events Clay
   renders nothing for; the plans that need specific subagent rows map
   them onto the existing `Tool` events instead.
7. **Adopt 0.7 opt-ins (attention/spawn/scopes/fabric) in the same cut
   as the pin** — rejected. Keeping the pin cut behavior-preserving
   except for the mapper makes failures attributable; the opt-ins are
   plans 121–123 with their own acceptance criteria.
8. **Adopt office/OCR, ACP, or AG-UI-in-daemon because 0.7 improves
   them** — rejected; consistent with `2026-08-21-1758` (no ACP/AG-UI as
   first-party bus) and the existing no-office stance.
9. **Rollback target `0.6.0` (as Prism’s migration doc suggests)** —
   rejected for Clay. Clay never ran 0.6.0; the last verified-good host
   state is exact `0.5.5`.

## Rationale and Evidence

- Prism 0.7.0 and `playwright-core@1.63.0` are the published current
  versions (`npm view` from the Clay repo, 2026-09-16); the 0.7 upgrade
  step 1 requires every `@arnilo/*` dependency and peer to bump together,
  and step 5 confirms no persisted-data migration is needed.
- `/home/arn/Projects/prism/docs/migrate-to-0.6.md` §1–§2 documents the
  Node `>=22` floor, the `playwright-core` `1.63.0` exact peer, and the
  graft peer range change; §5 documents folded fixes that need no host
  action (durable concurrent tool rounds, content-less tool results,
  `redactSecrets` fast path).
- `/home/arn/Projects/prism/CHANGELOG.md` `[0.7.0]` documents the
  attention compiler, host-owned spawn, work scopes, and fabric as
  opt-in; `docs/migrate-to-0.7.md` §1–§3 (ACP matching, router facade,
  ACP launcher) are the only hard refusals and none applies to
  clay-agent.
- Clay’s mapper evidence: `src/server/agent/run.rs` `map_event` has arms
  for the named lifecycle/tool/permission/delta types, an `agent_suspended`
  arm whose comment records the spurious-`Started` incident, and a
  `_ => AgentWireEvent::Started` catch-all; `src/server/agent.rs`
  asserts that a `provider_turn_finished` without usage hits the
  catch-all. That assertion is updated by plan 120 to expect a drop.
- Current pin evidence: `clay-agent/package.json` has the seven families
  at exact `0.5.5`, `better-sqlite3@13.0.3`, `playwright-core@1.61.0`,
  and `engines.node >= 20`; `.github/workflows/ci.yml` already runs
  Node 24, so the floor bump changes no CI leg.
- Precedent: every prior Prism pin cut logged before implementation
  (`2026-09-02-0121` 0.4.0, `2026-09-06-0432` 0.5.0, `2026-09-07-2149`
  0.5.1); 0.5.2–0.5.5 were minor increments under the 0.5.0/0.5.1
  decisions.

## Consequences

- Positive: clay-agent is on the supported Prism line before the Phase 5/6
  work that needs 0.7 APIs; browser/Obscura work stops being tested
  against an unsupported `playwright-core` peer; the Node floor matches
  what CI and the dev host already run; the event mapper can no longer
  synthesize fake `Started` events for unknown types (including 0.7
  telemetry and subagent lifecycle), so a future Prism event type cannot
  silently pin a run open.
- Risks/follow-up: plans 121–123 must keep the pin cut’s
  behavior-preserving property honest (no opt-in enabled inside 120);
  `attention_compiled`, `subagent_*`, and `delegation_*` stay unrendered
  until the plan that maps them; the drop-everything default means a
  future Prism lifecycle type that Clay *should* render needs an explicit
  arm (visible in the mapper, not silent).
- Conditions for revisiting: Prism publishes another lockstep with host
  work (0.8+); clay-agent gains an ACP launch path, a router facade call,
  a Postgres/office dependency, or a raw `provider.generate` site; a
  dropped event type turns out to carry user-visible state the transcript
  needs; or Node 22 approaches end-of-life.
