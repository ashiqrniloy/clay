# Decision: Prism 0.5.1 clay-agent family pin set; host request-policy stopgap deleted

## Decision

`clay-agent` moves its live Prism pins from exact `0.5.0` to exact `0.5.1`
for the same seven adopted families — `@arnilo/prism`, `@arnilo/prism-core`,
`@arnilo/prism-providers`, `@arnilo/prism-coding-tools`,
`@arnilo/prism-web-tools`, `@arnilo/prism-memory`, `@arnilo/prism-mcp` —
keeping direct `better-sqlite3@13.0.3` and `playwright-core@1.61.0`. On the
same cut, Clay deletes the `providerRequestPolicies:
createSessionCachePolicy()` stopgap from both `createAgent` sites in
`clay-agent/src/host.ts`: Prism 0.5.1's kernel fills missing
`options.sessionId` / `options.cacheKey` from the kernel session id (host
providerOptions still win) and stamps default cache breakpoints for
cache-control models, so the host policy is redundant. Per-prompt effort
moves to the session entry point (`AgentConfig.thinkingLevel` /
`RunOptions.thinkingLevel` on `session.stream`) instead of hand-merging
`applyThinkingLevelForModel` into `providerOptions`; `parseThinkingLevel`
stays as the fail-closed RPC validator and `thinkingLevelsForModel` stays on
`model.list`. Clay adds no `cache.mode` knob, no
`applyDefaultProviderRequestOptions` call (clay-agent has no raw
`provider.generate` site), and does not adopt office/ACP/AG-UI/antigravity
in the daemon. This closes the follow-up owed by decision
`2026-09-07-1325` (Prism-side enforcement has shipped).

## Context

Prism 0.5.1 (released 2026-09-07, upstream plan 066) is an additive lockstep
bump on 0.5.0: all 10 publishable manifests move `0.5.0` → `0.5.1`, internal
ranges `^0.5.0` → `^0.5.1`, no removals. It implements the mechanism Clay
requested in the 2026-09-07 defect report: `applyDefaultProviderRequestOptions`
fills missing session/cache correlation at the kernel choke point (covering
OM worker and compaction internal call sites that bypass host-visible
config), and `ProviderRequirementError` (`ERR_PRISM_PROVIDER_REQUIREMENT`)
fails fast before fetch when a provider-mandatory field is still missing —
replacing the opaque OpenCode Go `400 MissingSessionID`. It also adds
default cache breakpoints (`system_prompt` + `last_stable_message`,
`cacheRetention: "short"`) for `cache_control` / `explicitBreakpoints`
models, thinking-level session options, `om:{session.id}` correlation for
observational memory, and agent-session-id reuse for LLM compaction.

Clay's `createSessionCachePolicy()` wiring was an explicitly temporary
stopgap (decision `2026-09-07-1325`) whose known limitation — OM worker
models on OpenCode Go still 400'd — is exactly what kernel-side construction
fixes. Plan 113 (`plans/113-Adopt-Prism-0.5.1.md`) owns the bump and the
host rewiring; this log records the pin + construction decision before the
bump, mirroring the 0.4 (`2026-09-02-0121`) and 0.5.0 (`2026-09-06-0432`)
pin decisions.

## Alternatives Considered

1. **Keep `createSessionCachePolicy` as an overlay** — rejected. The kernel
   already fills session/cache keys; a redundant host policy hides coverage
   holes and contradicts 1325 ("hosts must not hand-wire per-provider
   request policies except as a temporary stopgap"). The stopgap existed
   only for session correlation.
2. **Keep `applyThinkingLevelForModel` hand-merge into `providerOptions`**
   — rejected. 0.5.1's session entry point (`RunOptions.thinkingLevel`) is
   the contract; the hand-merge is the 0.5.0 host workaround the release
   retires. Adapter helper remains for custom generate sites, which
   clay-agent does not have.
3. **Add a Clay `cache.mode` config knob to opt out of default breakpoints**
   — rejected. Adopting 0.5.1 includes its P2 default cache behavior; a knob
   is speculative until cache cost is a measured problem.
4. **Range pins (`^0.5.1`) or partial bump** — rejected. Project pattern is
   exact reviewed pins, and 0.5.1 is lockstep (a single-family bump creates
   the 0.5.0/0.5.1 mix the migration forbids).
5. **Wrap raw `provider.generate` with `applyDefaultProviderRequestOptions`**
   — rejected. Clay has no raw generate site; the kernel path covers all
   clay-agent runs including OM and compaction workers.

## Rationale and Evidence

- Prism 0.5.1 is additive over 0.5.0: new exports
  `applyDefaultProviderRequestOptions`, `ProviderRequirementError`,
  `ApplyDefaultProviderRequestOptionsContext`; session/cache fill, default
  breakpoints, thinking session options, OM `om:{id}` correlation, and
  compaction session-id reuse per `CHANGELOG.md` `[0.5.1]` and upstream plan
  066 (`/home/arn/Projects/prism/plans/066-Provider-Request-Construction-And-0-5-1.md`).
- `ProviderRequirementError` is thrown before fetch on raw
  `provider.generate` calls only; Prism-owned session runs cannot hit it,
  and its messages carry no request bodies or secrets. Clay maps unexpected
  provider failures through the existing `rpcError` + redactor path.
- Decision `2026-09-07-1325` pre-committed this outcome: "when Prism ships
  deterministic enforcement, delete the host-side policy wiring and
  re-verify opencode-go end-to-end." Prism shipped it; this decision
  executes the deletion and plan 113's manual test plan re-verifies
  OpenCode Go (first prompt and OM worker turn, no host policy).
- The seven-family pin set, subpath-only imports, explicit
  hyper/commandcode loads, MCP via `connectMcpTools` only, and the
  office/ACP/AG-UI/antigravity exclusions carry over unchanged from
  `2026-09-06-0432`; only versions and the request-construction stance
  change.
- No persisted-data migration; rollback is re-pinning exact `0.5.0` +
  `npm ci`.

## Consequences

- Positive: one authoritative request-construction point covers every
  clay-agent run including OM workers (the stopgap's known hole); OpenCode
  Go's `x-opencode-session` flows without host policy; typed fail-fast
  replaces opaque upstream 400s; default cache breakpoints arrive for
  cache-control models with no Clay code; thinking effort uses the
  supported session option; host.ts loses both the policy lines and the
  hand-merged thinking block.
- Risks/follow-up: plan 113 must verify default breakpoints do not surprise
  on cost-sensitive cache-control models (record in the manual test plan;
  add a knob only on measured need); `ProviderRequirementError` text may
  surface as `-32000` messages — never log request bodies; OM `om:`
  correlation ids are correlation data, not secrets.
- Conditions for revisiting: Prism changes the kernel fill semantics or
  default breakpoint set in a breaking way; cache cost on cache-control
  models becomes a measured problem; a future lockstep (0.6+) reintroduces
  breaking host work; clay-agent gains a raw `provider.generate` site (then
  adopt `applyDefaultProviderRequestOptions` there).
