# Decision: Prism 0.5.0 clay-agent family pin set

## Decision

`clay-agent` moves its live Prism pins from exact `0.4.0` to exact `0.5.0`
for the seven adopted families — `@arnilo/prism`, `@arnilo/prism-core`,
`@arnilo/prism-providers`, `@arnilo/prism-coding-tools`,
`@arnilo/prism-web-tools`, `@arnilo/prism-memory`, `@arnilo/prism-mcp` — plus
a direct `better-sqlite3@13.0.3`. Imports stay subpath-only
(`@arnilo/prism-core/credentials/node`, `@arnilo/prism-core/sessions/sqlite`,
`@arnilo/prism-core/validation/json-schema`, `@arnilo/prism-providers/<adapter>`).
Hyper and Command Code are loaded explicitly
(`@arnilo/prism-providers/hyper`, `@arnilo/prism-providers/commandcode`).
MCP is used exclusively through `@arnilo/prism-mcp`'s public API
(`connectMcpTools`); clay-agent never imports MCP SDK modules directly.
The daemon keeps its explicit host loads and does not adopt
`@arnilo/prism-office`, `@arnilo/prism-acp-agent`, `@arnilo/prism-ag-ui`, or
any antigravity package (removed upstream in 0.5; Phase 10 stays a direct
`agy` integration).

## Context

Prism 0.5.0 (released 2026-09-06) is a lockstep cut: all 10 publishable
manifests move `0.4.x` → `0.5.0`, internal ranges `^0.4.0` → `^0.5.0`, and
package names/subpaths stay valid. Plan 109 (`plans/109-Phase2.1-Coding-Agent-Defects-and-UX-Improvements.md`)
was stopped mid-execution because task I4 (reasoning-effort control) was
blocked by a Prism 0.4.0 thinking defect (silent drop of out-of-set effort,
no model-aware snapping). Prism 0.5.0 fixes exactly that path with
`applyThinkingLevelForModel` and declared `capabilities.thinkingLevels`
(defect report `/home/arn/Projects/prism/2026-09-05-prism-thinking-level-gaps-report.md`).
The user directed plan 109 to adopt Prism 0.5.0 first, record tasks for all
necessary changes, and align `roadmap.md` — including the MCP protocol update
and thinking-effort changes. This log records the pin set decision before the
bump, mirroring the 0.4 pin decision (`2026-09-02-0121`).

## Alternatives Considered

1. **Stay on 0.4.0 and patch thinking in Clay** — rejected. 0.4 thinking is
   the I4 blocker; 0.5 is the upstream fix and a lockstep cut. Patching
   Clay-side would duplicate the upstream adapter and fight future releases.
2. **Partial bump: only `@arnilo/prism`** — rejected. 0.5 is lockstep; peers
   and subpaths across families are `^0.5.0`. A single-family bump creates a
   0.4/0.5 mix the migration forbids.
3. **Range pins (`^0.5.0`)** — rejected. Project pattern (0121) is exact
   reviewed pins for `@arnilo/prism*`; `better-sqlite3` is a native ABI
   dependency (12 → 13 N-API rewrite) and exact pins are the safe default.
4. **Keep MCP on monolithic `@modelcontextprotocol/sdk` 1.30.0** — rejected.
   0.5 removes it from `@arnilo/prism-mcp`'s graph; clay-agent imports no SDK
   types and stays behind `connectMcpTools`, so no direct SDK pin is needed.
5. **Adopt `@arnilo/prism-office` / ACP / AG-UI now** — rejected. No
   coding-agent or store requirement justifies them; roadmap keeps them out of
   the daemon. `prism-antigravity-agent` was removed from the 0.5 workspace
   (`CHANGELOG.md` `[0.5.0]`); Phase 10 remains a direct `agy` integration.

## Rationale and Evidence

- `docs/migrate-to-0.5.md` (released): lockstep cut, 10 publishable
  manifests; breaking surface is 27 removed dead exports, MCP SDK module move,
  two thinking-effort wire moves, and two hardening behavior changes
  (tenant-aware store factories; child-process env allow-list
  `buildChildEnv` / `DEFAULT_CHILD_ENV_INHERIT`). No persisted-data migration;
  rollback is pinning previous `0.4.x` exact pins.
- Dependency majors: `better-sqlite3` 12 → 13 (optional peer of
  `prism-core`) is an N-API rewrite with bundled prebuilt binaries, no API
  removals; `@napi-rs/keyring` 1.x → 2.0 makes locked/inaccessible keychain
  reads/deletes reject with typed errors (`CredentialStoreLockedError`,
  `CredentialStoreUnavailableError`) instead of silent `undefined`/`false`;
  missing credentials still `undefined`.
- MCP (breaking for hosts): `@arnilo/prism-mcp` now depends on modular v2
  packages (`@modelcontextprotocol/client` + `@modelcontextprotocol/server`
  `2.0.0` exact pins) instead of monolithic `@modelcontextprotocol/sdk`
  1.30.0; spec target 2026-07-28; public surface (`createPrismMcpServer`,
  `createPrismMcpWebHandler`, `connectMcpTools`) keeps its shape. Draft-era
  task vocabulary fails closed. Clay imports no SDK modules.
- Thinking: `applyThinkingLevelForModel(base, level, model)` replaces
  `applyThinkingLevel` (family resolution + snap + merge in one call);
  pickers gate on `model.capabilities?.thinkingLevels` via
  `thinkingLevelsForModel`; Anthropic emits `output_config: { effort }`;
  xAI sends `reasoning_effort`; snapping replaces silent drop; `google` and
  `output_config_effort` compat families added. RunOptions and persisted
  shapes unchanged.
- Adapting facts: first-party provider catalog is 18 adapters in 0.5
  (hyper/commandcode added in 0.4.1/0.5); both follow the standard factory
  contract. `@arnilo/prism-antigravity-agent` workspace/package removed in
  0.5 (`CHANGELOG.md`).
- Phase 2.1 owns the cut per `roadmap.md` (Prism 0.5.0 lockstep section).

## Consequences

- Positive: 0.5 unblocks I4 (thinking effort); lockstep pins keep the graph
  homogeneous; sqlite 13 N-API prebuilds simplify installs; no persisted
  schema migration; rollback is pinning 0.4.x + `npm ci`.
- Risks/follow-up: tenant-aware store factories mean clay-agent's durable
  `createSqlitePersistence` call must pass the existing `TENANT = "clay"`
  scope or fail; child-process env must not rely on ambient `process.env`
  (pass the allow-list explicitly); locked keychain must surface typed
  errors, not empty-vault behavior; MCP SDK v2 module imports only inside
  `@arnilo/prism-mcp`, never in clay-agent; grep the 27 removed exports
  after the bump. Plan 109 executes these.
- Revisit if: Prism ships a 0.5.x that changes subpath export maps, the
  SQLite persistence schema, or the MCP public surface; or a later lockstep
  (0.6+) reintroduces breaking host work.
