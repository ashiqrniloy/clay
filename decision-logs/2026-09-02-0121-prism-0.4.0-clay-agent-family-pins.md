# Decision: Prism 0.4.0 clay-agent family pin set

## Decision

For Phase 0, `clay-agent` pins exactly `@arnilo/prism@0.4.0`,
`@arnilo/prism-core@0.4.0`, `@arnilo/prism-providers@0.4.0`, and a direct
`better-sqlite3@12.11.1`, importing family subpaths only
(`@arnilo/prism-core/credentials/node`, `@arnilo/prism-core/sessions/sqlite`,
`@arnilo/prism-core/validation/json-schema`,
`@arnilo/prism-providers/<adapter>`). The unused `@arnilo/prism-model-router`
dependency is dropped (no subpath adoption now). `@arnilo/prism-coding-tools`,
`prism-web-tools`, `prism-memory`, and `prism-mcp` are deferred to Phase 1;
`prism-antigravity-agent` to Phase 6; `prism-office`, `prism-acp-agent`, and
`prism-ag-ui` are never adopted in the daemon.

## Context

Prism 0.4.0 consolidates 62 package manifests into 11 active families with
explicit subpath exports. `clay-agent` currently carries 22 exact 0.3.0
`@arnilo/prism*` pins (credentials, session store, tool validator, model
router, 16 single-provider packages). The roadmap's Phase 0 required a logged
pin set before implementation (roadmap open decision 6), and the Phase 0 plan
(`plans/106-Phase0-Prism-0.4.0-Family-Migration-and-Verification.md`) makes the
pin set its first task.

Two shapes were evaluated in planning: (A) migrate only the live daemon graph
now, pinning Phase 1 families later; (B) also pin Phase 1 families now to
avoid a second migration pass. B was rejected: `prism-web-tools` requires
`prism-mcp`, which would fight the `phase25_dependencies_deny_acp_agui_mcp`
Rust deny test, and nothing in the daemon imports those families yet.

## Alternatives Considered

1. **Pin Phase 1 families now (Option B)** — rejected. Pulls `prism-mcp` into
   a phase whose deny test forbids MCP; no code uses those imports yet.
2. **Keep 16 `@arnilo/prism-provider-*` 0.3 packages beside the family** —
   rejected. 0.4 ships no wrapper packages; one family plus subpath imports
   replaces them, and mixing 0.3/0.4 manifests is what the migration forbids.
3. **Keep `prism-model-router` as `@arnilo/prism-core/governance/model-router`**
   — rejected. No daemon import exists; Phase 6 can add the subpath when the
   model router is actually wired.
4. **Range pins (`^0.4.0`)** — rejected. Project pattern is exact reviewed
   pins for `@arnilo/prism*`; native `better-sqlite3` ABI changes make exact
   pins the safe default.

## Rationale and Evidence

- Prism 0.4.0 migration guide (`/home/arn/Projects/prism/docs/migrate-to-0.4.md`):
  consolidation is import-level; explicit subpaths replace retired packages;
  "not a database/data migration"; rollback is restoring the 0.3 lockfile and
  `npm ci`.
- `@arnilo/prism-core@0.4.0` exports cover every daemon need:
  `./credentials/node` (`openEncryptedCredentialStore`,
  `createKeychainCredentialStore`, `createStoredCredentialResolver`),
  `./sessions/sqlite` (`createSqlitePersistence`, `SqlitePersistence`),
  `./validation/json-schema` (`createJsonSchemaToolArgumentValidator`).
- `@arnilo/prism-providers@0.4.0` exports all 16 adapter subpaths clay-agent
  loads; `createOpenAIProviderPackage` and peers keep the same factory option
  shape under names like `@arnilo/prism-providers/openai`.
- `better-sqlite3` is already a transitive 0.3 resolution at `12.11.1` and
  matches the `@arnilo/prism-core` peer range `^12.11.1`; pinning it directly
  in `clay-agent` makes the native addon explicit and stable.
- All 11 family packages are published at exactly `0.4.0` in the local Prism
  repository, so exact pins resolve.
- Existing evidence: SQLite fixtures round-trip with no migration API
  (`createSqlitePersistence` reopen); vault/SQLite file modes unchanged.

## Consequences

- Positive: daemon dependency list drops from 22 Prism pins to 3 families +
  1 native pin; imports are explicit subpaths; deny-test story stays honest;
  rollback is a two-file git checkout + `npm ci`.
- Risks/follow-up: Phase 1 must add `prism-coding-tools`, `prism-web-tools`,
  `prism-memory`, `prism-mcp` (with `better-sqlite3` for SQLite subpaths) and
  narrow the MCP deny test then; Phase 6 adds `prism-antigravity-agent@0.4.0`
  and the model-router subpath if wired.
- Revisit if: Prism ships a 0.4.x that changes subpath export maps or the
  SQLite persistence schema, or if a Phase 1 family turns out to require a
  package outside the approved family list.
