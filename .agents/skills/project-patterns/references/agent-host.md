# Agent Host

- First-party agents run in a Clay-owned Node >= 20 child (`clay-agent`) via Prism `createAgent` / `createAgentSession` / `AgentEvent`. Never inside `deno_core`. ACP remains out of the first-party path.
- `clay-agent` keeps its Clay-owned internal protocol to the Rust server. The server adapts bounded events into AG-UI for the React-facing stream over Tauri channels; AG-UI is not a daemon replacement and does not add a localhost listener.
- Clay server owns session identity, transcript, selected profile/provider/model, and mutation. React paints and forwards composer input. Typing/paint never wait on the daemon.
- Package JS cannot spawn or speak to the daemon. Core spawn, not a package-triggered process grant.
- Credentials: Clay vault + Prism credential resolvers. No `process.env`, no secrets in events/logs/menus/a11y.
- Agent profiles are `AgentDefinition`s registered by packages, not compiled core stubs. `@clay/chat` registers Chat (no tools). `@clay/coding-agent` (Phase 29) registers Coding Agent. Later Work/PA/Research are more packages on the same kernel, store, and `agent.*` APIs.
- Coding-agent CLI parity uses Prism tool factories plus Clay `ReadOperations`/`WriteOperations`/`EditOperations` over the document registry. Do not use `createAcpFilesystemOperations` or ACP `fs/*`.
- Host-owned binaries (Obscura engine, graft CLI, `computer-use-linux` MCP, `agy`) follow one pattern: fail-closed resolution, daemon-managed lifecycle, capabilities hidden when absent, never package-spawned.
- Acceptance policy: workspace = full agent freedom; host reads free, host writes outside workspace gated on explicit permission; opt-in full-autonomy toggle (clay + `st` alike).
- Session trees are pi-model JSONL trees (`id`/`parentId`, `/tree`, branch summaries, `/fork`/`/clone`) linked to document version checkpoints at task boundaries; `st` iterations checkpoint git + documents + session entry together so any branch is discardable post hoc (three layers, one action).
- One SQLite session/branch/checkpoint store serves clay + `st`, keyed by stable workspace identity. Clay-owned FTS searches current-workspace user/agent messages, branch summaries, plan/task metadata, and OM reflections; raw tool output stays out by default. Search results resume/open exact tree entries but never become agent context without explicit user action; `st` contributes workflow labels, never a second store.
- Pin `@arnilo/prism*` and AG-UI packages to exact reviewed versions. Live pins are Prism 0.5.1: the seven adopted families (`@arnilo/prism`, `@arnilo/prism-core`, `@arnilo/prism-providers`, `@arnilo/prism-coding-tools`, `@arnilo/prism-web-tools`, `@arnilo/prism-memory`, `@arnilo/prism-mcp`) at exact `0.5.1` plus direct `better-sqlite3@13.0.3`; import explicit subpaths only (`@arnilo/prism-core/credentials/node`, `@arnilo/prism-core/sessions/sqlite`, `@arnilo/prism-providers/<adapter>`); never retired 0.3 package names or the 27 exports removed in 0.5. Provider-mandatory wire requirements (e.g. OpenCode Go's required `x-opencode-session`) are Prism-side knowledge, enforced deterministically since 0.5.1 (kernel fills `options.sessionId`/`cacheKey`, default cache breakpoints, `ProviderRequirementError` fail-fast): hosts never hand-wire per-provider request policies — do not register `createSessionCachePolicy` or other session-policy overlays on `createAgent`. Per-prompt effort goes through `RunOptions.thinkingLevel` on `session.stream`, not hand-merged `providerOptions`. MCP goes through `@arnilo/prism-mcp` public API only — never import SDK v2 modules in clay-agent. - External coding agents are direct core-owned runtimes, never Prism providers or package-spawned processes. Their adapters expose a small lifecycle/event bridge plus declared capabilities; vendor loop/session context stays with the vendor while Clay owns the delegation record, policy projection, lifecycle, redaction, and UI truthfulness. Translate Clay tools through MCP separately from agent control. Claude Code uses its Agent SDK with isolated settings, explicit tools/MCP, and approval mediation; Antigravity headless uses configured policy and must advertise no live Clay approval until a documented control protocol exists. PTY is fallback for native vendor controls, not a semantic adapter. Decision: `decision-logs/2026-09-02-1440-direct-external-coding-agent-adapters.md`.
- Provider/model/agent/setup pickers are Command Centre session kinds, not extra dropdown widgets. Entry-surface buttons invoke the same commands.
- Pin `@arnilo/prism*` and AG-UI packages to exact reviewed versions.
