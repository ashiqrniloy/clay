Legacy, reserved & removed

declared-name inventory decisions

table — reserved kind, no specimen

table is a reserved package-facing kind with no recipe family in any design system and no consuming surface. It gets no specimen and no invented keys: a table surface must declare a table.default.* family (and the kind must appear in the component catalog) before it ships. Bounds allow it; the contract does not have it yet.

chat.default — removed, not re-skinned

The 12 chat.default.* keys are deleted with the chat surface (tasks 23–24), so they get no specimen and are not carried into @clay/design-instrument (130 keys, inventory finding 1). The launcher becomes the landing surface instead: a tab holds one workspace and one agent, and the agent is one of its two views.

card.default — legacy family, keep or drop

card.default.root.{rest,hover} is declared in both reference packages but appears in no component-kind list and no CSS module. Specimens are shown above so the decision is visible: either the card becomes a listed kind with a real consumer, or the two keys go with the reference packages. Recommendation: drop the keys (they are unconsumed dead data) unless a card surface is planned.

welcome.default, transientMenu.default, completion.default — not in the contract

Core fallbacks exist for these names but no shipped package declares a family for them. The new package must not invent keys for them (task 10 decides whether the core fallbacks stay) — the transient menu we do ship is menu.default.*, shown above.
